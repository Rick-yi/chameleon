# 31 · 点名汇总一致性与请求解包修复

> 对应问题清单 docs/26 的 P1-39 / P1-40：二次进入课节时，学员方块显示“已点名/缺勤”，但顶部汇总仍是 0。
> 本轮同时修复了一个影响报名、转学员、点名确认的前端通用问题。

---

## 一、点名汇总一致性

- 顶部增加两个明确口径：
  - **已点名 N 人**：本节已有出勤记录；
  - **本次待提交 M 人**：尚未确认的学员。
- 到课/请假/缺勤三个统计改为包含全部学员（已点名 + 待提交），与方块总数一致。
- 下方补充“本次待提交：到课 a · 请假 b · 缺勤 c”，避免把已点名数据重复计入。
- 已点名时显示提示：已点名学员为只读，如需修改先点方块上的「撤销」。
- 确认按钮显示待提交人数，全部点完时禁用。
- 确认/撤销后同步更新课节卡片的“应到/已点名/部分点名”状态，不需要刷新页面。

## 二、跳过原因持久展示

原来课时不足的学员只在 toast 里提示一次，转身就看不到。现在：

- 确认后页面保留一条警告提示：“X 人已消课；Y 人未消课”；
- 下方逐条列出学员姓名与原因（如“未购买该课程课包，无课时可消”“剩余课时不足”）；
- 关闭提示或切换课节后清除；
- 后端仍然保留出勤记录、不扣课时、不影响其他学员，不会把余额扣成负数。

## 三、前端请求解包修复

请求拦截器已经统一返回 `CommonResult.data`，但以下位置仍按完整响应读取 `res.data`，导致拿到 undefined：

| 位置 | 原问题 | 修复 |
|---|---|---|
| 点名确认 | `skippedList` 永远为空，跳过原因不显示 | 直接使用返回对象 |
| 学员列表「报名」 | 下单后的订单号 undefined，收款弹窗无法提交 | 直接使用返回的订单号 |
| 学员详情「报名购课」 | 同上 | 同上 |
| 线索「转学员」 | 新学员 ID undefined，后续报名失败 | 直接使用返回的学员 ID |

## 四、验证记录

| 场景 | 结果 |
|---|---|
| 二次进入已部分点名的课节 | 应到 4、已点名 2、待提交 2；三个状态合计 4 |
| 确认剩余 2 人 | 李小红未购课被跳过，页面保留“0 人已消课；1 人未消课”及原因 |
| 全部点完 | 已点名 4，确认按钮禁用，课节卡片变为“已点名” |
| 学员列表报名并收款 | 订单 PAID、实收 3600、课时账户 +22 |
| 课节卡片状态 | 确认/撤销后无需刷新即同步 |

## 五、边界

- 点名确认仍然只提交“未点名”学员，已点名学员必须先撤销才能修改。
- 跳过原因来自后端出勤记录备注，历史数据没有备注时只显示数量。
