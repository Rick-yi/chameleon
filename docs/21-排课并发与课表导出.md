# 21 · 排课并发约束与课表异步导出

> 补上排课最后一块并发短板，并把课表导出接入通用异步导出。

---

## 一、教师 / 教室并发唯一约束

### 背景

之前只有「班级 + 时段」有数据库唯一键。两个教务同时操作时：

- 同一班级同一时段 → 被唯一键拦住；
- 同一老师给不同班上同一时段 → 只有应用层检查，并发下都能成功；
- 同一教室被不同班占用 → 同上。

### 做法

沿用班级时段的生成列方案，新增两个生成列 + 唯一索引：

| 列 | 表达式 | 说明 |
|---|---|---|
| `ACTIVE_TEACHER_KEY` | `TEACHER_ID｜日期｜开始时间`（仅 `STATUS='NORMAL'`） | 同一老师同一时段只能一节课 |
| `ACTIVE_ROOM_KEY` | `UPPER(TRIM(CLASSROOM))｜日期｜开始时间`（仅正常课节） | 同一教室同一时段只能一节课，**大小写不敏感** |

迁移时先清理历史重复（同教师、同教室分别去重，保留每组最早一条，其余置为已取消），再建索引。
本次执行清理了 **180 条同教室同时段的重复课节**（全部来自压测租户的合成数据）。

### 应用层配合

- 教室比较统一为「去首尾空格 + 忽略大小写」，`B201` 与 `b201` 不再被当成两个教室；
- `add()` 捕获 `DuplicateKeyException` 时按索引名给出具体原因：
  - `UK_SCHEDULE_ACTIVE_TEACHER` → 「该教师在 X 时段已有排课」；
  - `UK_SCHEDULE_ACTIVE_ROOM` → 「该教室在 X 时段已被占用」；
  - 其余 → 「该班级在 X 时段已有排课」。

验证：直接插入同教师/同教室重复行，分别被 `UK_SCHEDULE_ACTIVE_TEACHER`、`UK_SCHEDULE_ACTIVE_ROOM` 拒绝；
用 `b201` 去抢已被 `B201` 占用的时段，应用层直接提示「教室【b201】…已被【素描基础 A1】占用」。

## 二、课表导出接入异步导出

课表导出会生成两个 sheet（课表清单 + 周视图），学期范围数据量不小，原来同步生成、直接写响应。

现在：

- `CourseScheduleExportService` 抽出 `buildSheets(...)`，同步导出与异步导出共用同一份行构建逻辑；
- 新增 `COURSE_SCHEDULE` 类型的 `BizExportBuilder`；
- 页面「导出课表」改为走 `runAsyncExport('COURSE_SCHEDULE', ...)`，后台生成完成后自动下载；
- 导出结果同样出现在报表页的「导出记录」中（按租户隔离，文件保留 3 天）。

验证：创建 `COURSE_SCHEDULE` 任务 → `SUCCESS` → 行数 4、文件名 `课表_20261023144823.xlsx`。
