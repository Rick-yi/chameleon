# 11 · 自动化规则（自动化中心）

> 目标：把教培机构每天重复的人工动作交给系统——点名结算、线索分配、收款与续费提醒，
> 让老师/教务/前台把时间花在「服务学员」而不是「追着表格跑」。

---

## 一、是什么

「自动化中心」（菜单：教务运营 → 自动化中心，路径 `/automation`）是所有自动化规则的统一入口：

- 每条规则一张卡片：**开关 + 参数 + 说明 + 最近一次执行结果**
- 规则默认**关闭**，开了才生效，避免上线即误操作
- 定时型规则每 10 分钟自动跑一次；实时型规则在业务动作发生时立刻生效
- 所有自动操作都写执行记录（谁、什么时候、影响了多少条、结果是什么），出问题可查、可撤销

## 二、现有规则

| 规则 | 编码 | 模式 | 解决什么 | 参数 |
|---|---|---|---|---|
| 课节自动结算 | `AUTO_SETTLE_ATTEND` | 定时 | 老师上完课晚上才想起来点名 → 课节结束超过宽限时间仍未点名的，自动按**缺勤**点名并按课程规则扣课 | 宽限时间（分钟，默认 120）、通知任课老师（默认开） |
| 线索自动分配 | `AUTO_ASSIGN_LEAD` | 实时 | 新线索没人认领 → 没有指定跟进人时，自动分配给**当前在跟线索最少**的招生顾问 | 排除的跟进人（逗号分隔，可空） |
| 续费预警提醒 | `AUTO_NOTIFY_RENEW_WARN` | 定时 | 预警生成了没人看 → 有待处理的续费预警时，给机构管理员发站内信 | 重复提醒间隔（小时，默认 24）、接收人角色码（默认 superAdmin） |
| 试听结束自动推进 | `AUTO_TRIAL_FOLLOWUP` | 定时 | 顾问约完试听忘了改状态 → 试听时间过后自动把预约置为已完成，并给跟进人发站内信提醒录结果、推进转化 | 宽限时间（分钟，默认 30）、提醒跟进人（默认开） |
| 未支付订单提醒 | `AUTO_NOTIFY_UNPAID_ORDER` | 定时 | 报名开单后家长不付款，钱悬在待收款里 → 超时未付的订单自动提醒管理员去收款 | 超时未付小时数（默认 24）、重复提醒间隔（小时，默认 24） |

> 两条提醒规则用「最近提醒时间」字段控制频率：提醒过一次后要等间隔时间到了才会再提醒，不会反复打扰。

## 三、关键设计

### 1. 规则用 SPI 注册，业务插件各管各的

```
biz-api   BizAutomationHandler（规则执行器接口）
biz       BizAutomationService（开关/参数/执行/记录）+ 定时任务 BizAutomationTimerTaskRunner
course    AutoSettleAttendHandler   （教务域的规则）
crm       AutoAssignLeadHandler     （招生域的规则）
student   AutoNotifyRenewWarnHandler / AutoNotifyUnpaidOrderHandler
```

- 业务插件实现 `BizAutomationHandler` 并注册成 Spring Bean，自动化中心自动收录
- 新增一条规则 = 新增一个 Handler，**不需要改自动化中心**
- 规则开关与参数存 `BIZ_AUTOMATION_CONFIG`（租户级），执行记录存 `BIZ_AUTOMATION_LOG`

### 2. 自动操作一律可撤销

- 自动结算生成的点名记录，和老师手工点的一样，可以在「点名消课」里**撤销**并回补课时
- 自动分配的线索，在「招生线索」里改跟进人即可
- 撤销动作会同步回 `BIZ_AUTOMATION_LOG` 的执行记录，方便复盘

### 3. 无登录态也能跑

定时任务里没有登录用户，因此：

- `CourseClassAttendServiceImpl.confirm()` 的操作人取登录态，取不到时用系统账号 `-1`
- 埋点记录（BIZ_EVENT）对未登录场景做了容错，不会因自动化执行失败

## 四、接口

| 接口 | 说明 |
|---|---|
| `GET /biz/automation/rule` | 规则列表（含开关、参数、最近执行情况） |
| `POST /biz/automation/toggle` | 开启/关闭规则并保存参数 |
| `POST /biz/automation/run` | 立即执行一条规则（手动触发） |
| `GET /biz/automation/log` | 执行记录分页 |

权限码：`/biz/automation/rule`、`/biz/automation/toggle`、`/biz/automation/run`、`/biz/automation/log`
（已随「自动化中心」菜单一并授予各租户超级管理员）

## 五、新增一条自动化规则（开发指引）

1. 在对应业务插件里实现 `BizAutomationHandler`：

```java
@Component
public class AutoXxxHandler implements BizAutomationHandler {
    @Override public String getRuleCode() { return "AUTO_XXX"; }
    @Override public String getRuleName() { return "规则名称"; }
    @Override public String getRuleDesc() { return "这条规则替用户省掉了什么操作"; }
    @Override public String getMode() { return "TIMER"; }   // TIMER 定时 / TRIGGER 实时
    @Override public List<AutomationParam> getParamDef() { ... }  // 前端据此渲染参数表单
    @Override public AutomationResult execute(AutomationContext context) {
        // context.getIntParam("xxx", 默认值)
        return AutomationResult.ok("处理了 3 条", 3);
    }
}
```

2. 实时型规则：在业务动作里判断开关再调用

```java
if (bizAutomationApi.isEnabled(AutoAssignLeadHandler.RULE_CODE)) {
    handler.assign(lead, bizAutomationApi.getParam(AutoAssignLeadHandler.RULE_CODE, "excludeUserName", ""));
}
```

3. 需要的话在 `_sql/chameleon_automation.sql` 里补一条定时任务（定时型规则共用「自动化规则执行」这一个任务）
