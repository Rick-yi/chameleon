# 08 · 部署与运维

> 面向自营 SaaS 版本的部署说明：本地/服务器/Docker 三种方式、数据库初始化顺序、备份恢复与日常巡检。
> 多租户相关约束见 [docs/04](04-教培SaaS产品方案.md)，报表与数据口径见 [docs/07](07-报表与看板规划.md)。

## 一、运行要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 17 | 运行与构建均需 17（本仓库内置 `.jdk/jdk-17`，仅本机使用） |
| Maven | 3.8+ | 构建用 |
| MySQL | 8.0 / 5.7 | 业务库 `chameleon` |
| Redis | 6 / 7 | 缓存、Sa-Token 会话、字典缓存 |
| Node.js | ≥ 18 | 仅构建前端时需要 |

## 二、数据库初始化顺序

按顺序执行，脚本都放在 `snowy-web-app/src/main/resources/_sql/`：

| 顺序 | 脚本 | 说明 |
|---|---|---|
| 1 | `snowy_mysql.sql` | 底座表（系统、字典、配置、任务、文件等） |
| 2 | `chameleon_platform.sql` | 平台域（租户、套餐） |
| 3 | `chameleon_tenant_migration.sql` | 租户字段迁移 |
| 4 | `chameleon_course.sql` | 课程域（课程/课包/班级/排课/点名） |
| 5 | `chameleon_student.sql` | 学员域（学员/订单/账户/流水/退费/预警/通知） |
| 6 | `chameleon_crm.sql` | 招生域（线索/跟进/试听） |
| 7 | `chameleon_finance.sql` | 财务域字段补充 |
| 8 | `chameleon_menu.sql` | 业务菜单（可重复执行） |
| 9 | `chameleon_p0_migration.sql` | P0 结构升级（幂等） |
| 10 | `chameleon_report_r2r4_migration.sql` | 报表菜单 ID 修复（可重复执行） |
| 11 | `chameleon_report_permission.sql` | 报表接口与按钮权限（可重复执行） |
| 12 | `chameleon_c1_migration.sql` | 课务/账务/报表结构升级（一次性） |

> 应用启动时 `P0SchemaMigration` 会做同样的**幂等**检查与补列，存量库漏跑脚本也能自愈；
> 一次性脚本（会报「列已存在」错误的）只用于全新初始化。

## 三、启动方式

### 3.1 命令行

```bash
export SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_URL='jdbc:mysql://<host>:3306/chameleon?useUnicode=true&characterEncoding=utf-8&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai'
export SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_USERNAME=root
export SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_PASSWORD='***'
export SPRING_DATA_REDIS_HOST=<redis-host>
export SPRING_DATA_REDIS_PORT=6379
export SPRING_DATA_REDIS_PASSWORD='***'
export SPRING_DATA_REDIS_DATABASE=1

mvn clean package -DskipTests
java -Djava.io.tmpdir=./tmp -jar snowy-web-app/target/snowy-web-app-3.0.0.jar
```

启动后：

- 后端接口：<http://localhost:82>
- 接口文档（Knife4j）：<http://localhost:82/doc.html>
- 前端：`cd snowy-admin-web && npm install && npm run dev`（默认 81 端口，代理到 82）

### 3.2 Docker

```bash
# 根目录已提供多阶段 Dockerfile（maven 构建 + JRE 运行）
docker compose -f snowy-web-app/src/main/resources/docker-compose.yml up -d --build
```

镜像内容与 compose 说明：

- 后端容器非 root 运行，端口 82；
- `app-data` 卷保存异步导出文件（保留 3 天自动清理），`app-logs` 卷保存日志；
- MySQL/Redis 数据分别落在 `mysql-data` / `redis-data` 卷。

## 四、环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_URL` | `localhost:3306/chameleon` | 业务库连接串，需带 `serverTimezone` |
| `SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_USERNAME` / `_PASSWORD` | `root` / `12345678` | 数据库账号 |
| `SPRING_DATA_REDIS_HOST` / `_PORT` / `_PASSWORD` / `_DATABASE` | `localhost` / `6379` / 空 / `1` | Redis 连接 |
| `SPRING_PROFILES_ACTIVE` | `local` | 选 `docker` 时使用容器内配置 |
| `TZ` | `Asia/Shanghai` | 时区，影响定时任务与日报 |

> 密码不要写进仓库；`application-docker.yml` 里的默认值仅用于本地 compose 演示。

## 五、日常运维

### 5.1 定时任务

启动时 `PlatformBootstrap` 自动登记并启用三类任务（租户级任务内部按租户遍历）：

| 任务 | cron | 说明 |
|---|---|---|
| 租户到期扫描 | 每天 01:00 | 到期租户停用 |
| 续费预警扫描 | 每天 02:00 | 生成续费预警 |
| 财务日汇总 | 每天 00:30 | 汇总前一天数据，供报表快路径与对账使用 |

`DEV_JOB.TENANT_ID` 记录任务归属租户（平台任务为 `0`）。

### 5.2 健康检查

- 进程存活：<http://127.0.0.1:82/doc.html> 有响应即可（本部署下该地址需要鉴权，返回 401 也说明进程正常）；
- 巡检脚本：`node scripts/health-check.mjs http://127.0.0.1:82`，失败返回非 0；
- 注意：应用刚启动后的第一个请求会触发字典缓存重建，冷启动瞬间可能偏慢，巡检脚本已放宽到 30 秒超时；
- 业务健康：登录后调用 `GET /finance/report/dashboard`，返回 `code=200`；
- 定时任务：管理端「系统运维 → 定时任务」中任务状态为「运行中」。

### 5.3 日志

- 应用日志：标准输出（容器内 `/app/logs`）；
- 操作日志：底座 `SYS_LOG`（`/dev/log/**`，仅平台运营可查）；
- 报表导出文件：`data/chameleon-export`，保留 3 天。

### 5.4 运维脚本

| 脚本 | 用途 | 用法 |
|---|---|---|
| `scripts/backup.sh` | 备份业务库并清理过期备份 | `MYSQL_PWD=... ./scripts/backup.sh 30` |
| `scripts/upgrade.sh` | 按顺序执行幂等 SQL 脚本 | `MYSQL_PWD=... ./scripts/upgrade.sh` |
| `scripts/health-check.mjs` | 存活 + 登录 + 关键接口巡检（失败返回非 0） | `node scripts/health-check.mjs http://127.0.0.1:82` |
| `scripts/bench-report.mjs` | 报表接口压测基线 | `node scripts/bench-report.mjs http://127.0.0.1:82 1,4,8` |
| `scripts/serve-dist.mjs` | 本地静态预览生产构建产物 | `node scripts/serve-dist.mjs 81` |

### 5.5 性能基线

`scripts/bench-report.mjs` 用于压测报表读接口（自动登录并轮询汇总/趋势/排行/看板/教务/招生接口）：

```bash
node scripts/bench-report.mjs http://127.0.0.1:82 6 15
```

2026-10-21 在演示环境（远程 MySQL/Redis，13 个报表/业务读接口轮询）实测：

| 并发 | 请求数 | P50 | P95 | 最大耗时 | 错误数 |
|---|---|---|---|---|---|
| 1 | 20 | 76ms | 203ms | 203ms | 0 |
| 4 | 80 | 149ms | 252ms | 281ms | 0 |
| 8 | 160 | 268ms | 596ms | 767ms | 0 |

> 报告数据随数据量与数据库链路变化，基线仅用于同环境对比；异常时优先看数据库慢查询、Redis 命中率与导出文件所在磁盘。

看板/汇总类接口有 5 分钟 Redis 缓存，缓存命中时响应更快；压测结果异常时优先看
数据库慢查询、Redis 命中率和导出文件所在磁盘。

### 5.6 备份与恢复

```bash
# 备份
mysqldump -h <host> -u root -p --single-transaction --routines chameleon > chameleon-$(date +%F).sql

# 恢复
mysql -h <host> -u root -p chameleon < chameleon-2026-01-01.sql
```

Redis 只承载缓存与会话，**不需要备份**；丢失后重新登录即可。

> 建议：每日全量备份 + 保留 30 天；上线前先在预发环境演练一次恢复。

## 六、多租户注意事项

| 主题 | 现状 | 说明 |
|---|---|---|
| 租户识别 | 登录页填「机构编码」 | 已登录请求只认会话里的租户，`X-Tenant-Id` 无法切换 |
| 业务表隔离 | MyBatis-Plus 租户拦截器 | 新增业务表必须在 `GlobalConfigure.TENANT_TABLES` 登记 |
| 缓存隔离 | 报表缓存 key 含租户；字典用「租户+字典编码」缓存 | 底座 easy-trans 的全局字典缓存仍共享，字典编码建议全局唯一 |
| 文件隔离 | 存储桶带租户前缀 | 本地存储落到 `<租户>-defaultBucketName/` 目录 |
| 机构数据范围 | 角色授权里配置 `scopeCategory` | 业务列表/报表按可见机构（校区）过滤，见 [docs/05](05-核心业务逻辑细化.md) |
| 套餐限额 | `studentLimit` / `campusLimit` / `funcConfig` | **当前仅存储未生效**，需人工关注 |

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `Access denied for user` | 环境变量未注入 | 按第三节导出数据库/Redis 环境变量 |
| 登录提示「无此权限」 | 角色缺少接口授权 | 管理端「角色管理 → 授权」补勾；报表接口见 `chameleon_report_permission.sql` |
| 报表数字与流水对不上 | 历史演示数据无流水 | 用 `GET /finance/report/reconcile` 查看差异说明（历史数据单独提示） |
| 导出报「无数据可导出」 | 筛选条件无数据 | 放宽时间范围；异步导出用 `GET /finance/report/export/async` |
| 单测报临时目录权限错误 | Windows 系统临时目录不可写 | 已通过 surefire `java.io.tmpdir` 指向工程内目录解决 |
