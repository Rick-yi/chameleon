# 08 · 部署与运维

> 面向自营 SaaS 版本的部署说明：Docker 一键部署与裸机部署两种方式、数据库初始化、环境变量、备份恢复与巡检。
> 多租户相关约束见 [docs/04](04-教培SaaS产品方案.md)，报表与数据口径见 [docs/07](07-报表与看板规划.md)。

## 二、数据库初始化

初始化脚本按固定顺序执行，**不要手工逐个导入**：

```bash
# 方式一：Node（需本机有 mysql 客户端）
node scripts/db-init.mjs --host 127.0.0.1 --port 3306   --user root --password '***' --database chameleon

# 方式二：Shell（服务器/容器内可用）
MYSQL_HOST=127.0.0.1 MYSQL_USER=root MYSQL_PWD='***' MYSQL_DB=chameleon   ./scripts/db-init.sh
```

要点：

- 固定顺序里**底座表补租户列必须早于按租户写关系数据的菜单脚本**；
- 默认会创建演示租户 `demo`；生产环境加 `--skip-demo`（或 `SKIP_DEMO=1`）跳过；
- 平台运营租户、`platformAdmin` 账号与角色由后端启动时的 `PlatformBootstrap` 自动创建；
- 结构变更（加列/索引/新表）由 `P0SchemaMigration` 在启动时幂等补齐，升级已有库不必手工跑 ALTER。

## 三、部署方式

### 3.1 Docker Compose（推荐）

编排文件：`snowy-web-app/src/main/resources/docker-compose.yml`，包含：

| 服务 | 说明 |
|---|---|
| `chameleon-web` | nginx 托管前端，`/api` 反向代理到后端，对外 80 |
| `chameleon-web-app` | 后端（prod profile），对外 82 |
| `chameleon-mysql` | MySQL 8，数据在 `mysql-data` 卷 |
| `chameleon-redis` | Redis 7，数据在 `redis-data` 卷 |
| `chameleon-db-init` | 一次性初始化：执行 `scripts/db-init.sh` 后退出 |

```bash
# 1) 可选：自定义数据库密码（默认 12345678，仅建议演示使用）
export MYSQL_ROOT_PASSWORD='<强密码>'
export SKIP_DEMO=1

# 2) 启动（首次会构建后端与前端镜像并初始化数据库）
docker compose -f snowy-web-app/src/main/resources/docker-compose.yml up -d --build

# 3) 查看初始化结果与后端健康状态
docker compose -f snowy-web-app/src/main/resources/docker-compose.yml ps
docker logs chameleon-db-init
curl -I http://127.0.0.1/favicon.ico
```

访问：

- 前端：<http://<服务器IP>/>
- 后端直连：<http://<服务器IP>:82/>
- 接口文档（需登录）：<http://<服务器IP>:82/doc.html>

持久化卷：

- `app-data` → `/app/data`（异步导出文件，保留 3 天）
- `app-logs` → `/app/logs`（文件日志）
- `upload-data` → `/defaultUploadFolder`（本地上传文件）
- `mysql-data` / `redis-data` → 数据库与缓存

### 3.2 裸机部署（jar + nginx）

```bash
# 1) 初始化数据库（首次）
MYSQL_HOST=127.0.0.1 MYSQL_USER=root MYSQL_PWD='***' MYSQL_DB=chameleon   SKIP_DEMO=1 ./scripts/db-init.sh

# 2) 构建后端
mvn clean package -DskipTests

# 3) 构建前端（.env.production 中接口地址留空，用相对路径 /api）
cd snowy-admin-web && npm ci && npm run build && cd ..

# 4) 启动后端（prod profile，所有连接信息走环境变量）
export SPRING_PROFILES_ACTIVE=prod
export SERVER_PORT=82
export MYSQL_HOST=127.0.0.1 MYSQL_PORT=3306 MYSQL_DB=chameleon
export MYSQL_USER=root MYSQL_PWD='***'
export REDIS_HOST=127.0.0.1 REDIS_PORT=6379 REDIS_DB=1 REDIS_PWD=''
export LOG_PATH=/var/log/chameleon
nohup java -Djava.io.tmpdir=/tmp/chameleon -jar snowy-web-app/target/snowy-web-app-3.0.0.jar >/dev/null 2>&1 &

# 5) nginx：托管 dist 并代理 /api
sudo mkdir -p /var/www/chameleon
sudo cp -r snowy-admin-web/dist/* /var/www/chameleon/
sudo cp deploy/nginx.bare.conf /etc/nginx/conf.d/chameleon.conf
sudo nginx -t && sudo systemctl reload nginx
```

> 前端生产包调用的是相对路径 `/api`，nginx 会去掉 `/api` 前缀转发到 `127.0.0.1:82`。

## 四、环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | `local` | 服务器部署必须设为 `prod` |
| `SERVER_PORT` | `82` | 后端端口 |
| `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_DB` | `127.0.0.1` / `3306` / `chameleon` | 业务库 |
| `MYSQL_USER` / `MYSQL_PWD` | `root` / 空 | 业务库账号（生产必须显式注入密码） |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_DB` | `127.0.0.1` / `6379` / `1` | Redis |
| `REDIS_PWD` | 空 | Redis 密码 |
| `LOG_PATH` | `./logs` | 文件日志目录（非 local profile 生效） |
| `JAVA_OPTS` | `-Xms512m -Xmx1024m` | JVM 参数 |
| `TZ` | `Asia/Shanghai` | 时区，影响定时任务与日报 |

本地开发仍使用 `application.properties` 中的 `local` 配置；`prod` 配置见 `application-prod.yml`，**不包含任何默认密码**。

## 五、日常运维

### 5.1 定时任务

启动时 `PlatformBootstrap` 自动登记并启用任务（租户级任务内部按租户遍历）：

| 任务 | cron | 说明 |
|---|---|---|
| 租户到期扫描 | 每天 01:00 | 到期租户停用 |
| 续费预警扫描 | 每天 02:00 | 生成续费预警 |
| 财务日汇总 | 每天 00:30 | 汇总前一天数据，供报表快路径与对账使用 |
| 自动化规则 | 每 10 分钟 | 执行已开启的定时型自动化规则 |
| 埋点归档 | 每天 03:30 | 按租户保留期清理 `BIZ_EVENT`（默认 90 天，可用 `DEV_CONFIG.BIZ_EVENT_RETAIN_DAYS` 覆盖） |

`DEV_JOB.TENANT_ID` 记录任务归属租户（平台任务为 `0`）。

### 5.2 健康检查

- 存活检查：`GET /favicon.ico` 返回 200 即进程正常（Docker healthcheck 用的就是它）；
- `GET /doc.html` 需要登录，返回 401 也说明进程存活，不适合作为探针；
- 巡检脚本：`node scripts/health-check.mjs http://127.0.0.1:82`，失败返回非 0；
- 业务健康：登录后调用 `GET /finance/report/dashboard`，返回 `code=200`；
- 定时任务：管理端「系统运维 → 定时任务」中状态为「运行中」。

### 5.3 日志

- 文件日志：`LOG_PATH` 目录（Docker 内 `/app/logs`，已挂载 `app-logs` 卷）；
- 操作日志：底座 `SYS_LOG`（`/dev/log/**`，仅平台运营可查）；
- 报表导出文件：`data/chameleon-export`，保留 3 天自动清理。

### 5.4 运维脚本

| 脚本 | 用途 | 用法 |
|---|---|---|
| `scripts/db-init.sh` | 空库初始化（固定顺序） | `MYSQL_PWD=... ./scripts/db-init.sh` |
| `scripts/db-init.mjs` | 同上，Node 版，支持 `--skip-demo` | `node scripts/db-init.mjs --skip-demo` |
| `scripts/backup.sh` | 备份业务库并清理过期备份 | `MYSQL_PWD=... ./scripts/backup.sh 30` |
| `scripts/upgrade.sh` | 已有库的增量/幂等脚本 | `MYSQL_PWD=... ./scripts/upgrade.sh` |
| `scripts/seed-demo-data.mjs` | 给空租户生成演示数据（课程/班级/学员/收款/课表/线索） | `node scripts/seed-demo-data.mjs --base https://域名/api --tenant 租户编码 --account 管理员 --password '***'` |
| `scripts/health-check.mjs` | 存活 + 登录 + 关键接口巡检 | `node scripts/health-check.mjs http://127.0.0.1:82` |
| `scripts/bench-report.mjs` | 报表接口压测基线 | `node scripts/bench-report.mjs http://127.0.0.1:82 1,4,8` |
| `scripts/serve-dist.mjs` | 本地静态预览生产构建产物 | `node scripts/serve-dist.mjs 81` |

### 5.5 性能基线

`scripts/bench-report.mjs` 用于压测报表读接口（自动登录并轮询汇总/趋势/排行/看板/教务/招生接口）：

```bash
node scripts/bench-report.mjs http://127.0.0.1:82 6 15
```

2026-10-21 在演示环境（13 个报表/业务读接口轮询）实测：

| 并发 | 请求数 | P50 | P95 | 最大耗时 | 错误数 |
|---|---|---|---|---|---|
| 1 | 20 | 76ms | 203ms | 203ms | 0 |
| 4 | 80 | 149ms | 252ms | 281ms | 0 |
| 8 | 160 | 268ms | 596ms | 767ms | 0 |

> 报表缓存 TTL 为 60 秒，收款/退费/消课提交后会主动失效；压测结果异常时优先看数据库慢查询与 Redis 命中率。

### 5.6 备份与恢复

```bash
# 备份（推荐用脚本，自动保留 30 天）
MYSQL_HOST=<host> MYSQL_USER=root MYSQL_PWD='***' ./scripts/backup.sh 30

# 恢复
mysql -h <host> -u root -p --default-character-set=utf8mb4 chameleon < backup/chameleon-YYYYmmdd-HHMMSS.sql
```

Redis 只承载缓存与会话，**不需要备份**；丢失后重新登录即可。

> 建议：每日全量备份 + 保留 30 天；上线前先在预发环境演练一次恢复。

## 七、多租户注意事项

| 主题 | 现状 | 说明 |
|---|---|---|
| 租户识别 | 登录页填「机构编码」 | 已登录请求只认会话里的租户 |
| 业务表隔离 | MyBatis-Plus 租户拦截器 | 新增业务表必须在 `GlobalConfigure.TENANT_TABLES` 登记 |
| 缓存隔离 | 报表缓存 key 含租户；字典用「租户+字典编码」缓存 | 底座 easy-trans 的全局字典缓存仍共享，字典编码建议全局唯一 |
| 文件隔离 | 存储桶带租户前缀 | 本地存储落到 `<租户>-defaultBucketName/` 目录 |
| 机构数据范围 | 角色授权里配置 `scopeCategory` | 业务列表/报表按可见机构（校区）过滤 |
| 套餐限额 | `studentLimit` / `campusLimit` / `funcConfig` | **当前仅存储未生效**，需人工关注 |

## 八、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `Access denied for user` | 环境变量未注入 | 检查 `MYSQL_PWD` / `REDIS_PWD` |
| 前端接口 404 | nginx 未配置 `/api` 代理或未去掉前缀 | 使用 `deploy/nginx.bare.conf`，确认 `proxy_pass .../` 结尾带斜杠 |
| 前端请求打到 127.0.0.1 | 构建时 `.env.production` 填了后端地址 | 接口地址留空，重新 `npm run build` |
| 菜单/业务数据中文乱码 | 初始化时 mysql 客户端字符集不是 utf8mb4（中文被双重编码） | 使用当前 `db-init.sh`（已带 `--default-character-set=utf8mb4`）；已乱码的库需备份后重新初始化 |
| 登录提示「无此权限」 | 角色缺少接口授权 | 管理端「角色管理 → 授权」补勾 |
| 报表数字与流水对不上 | 历史演示数据无流水 | 用 `GET /finance/report/reconcile` 查看差异说明 |
| 导出报「无数据可导出」 | 筛选条件无数据 | 放宽时间范围 |

## 九、上线安全加固

| 项 | 操作 |
|---|---|
| 平台管理员密码 | 首次登录后立即修改 `platformAdmin` 密码 |
| 演示租户 | 生产初始化后禁用：`UPDATE T_TENANT SET STATUS='DISABLED' WHERE CODE='demo';`，并禁用其 `superAdmin` 账号 |
| 数据库/Redis 密码 | 不要使用 compose 默认的 `12345678`，通过 `MYSQL_ROOT_PASSWORD` 注入强密码 |
| 端口暴露 | compose 默认只暴露 80/82；MySQL(3306) 与 Redis(6379) 仅在容器网络内可访问 |
| HTTPS | 在 nginx 上配置证书并 301 跳转 HTTPS；`X-Forwarded-Proto` 已透传 |
| 备份 | 配置每日 `scripts/backup.sh` 定时任务，并定期验证恢复 |
| 私钥与证书 | SSH 私钥由运维本机保管（不入库）；HTTPS 证书 `<部署目录>/ssl/<域名>.pem`（644）与私钥 `<域名>.key`（600）在服务器，均不入库 |

## 十、生产 nginx 配置（aiglobe.xin）

生产实际运行的 nginx 配置是 HTTPS 形态：80 跳 443、443 + http2、证书、`proxy_pass http://app:82/`、`/api/druid/` 拒绝公网访问。它与仓库里的 `deploy/nginx.conf.template`、`deploy/nginx.bare.conf`（纯 HTTP 模板）**不是同一份**。

| 项 | 说明 |
| --- | --- |
| 权威副本 | `deploy/nginx.prod.conf`，与服务器 `/opt/chameleon/nginx.conf` 逐字节一致 |
| 服务器挂载 | `/opt/chameleon/nginx.conf` → 容器 `/etc/nginx/conf.d/default.conf`（只读） |
| 生效方式 | `docker exec chameleon-web nginx -t && docker restart chameleon-web` |
| 重建方式 | `scp deploy/nginx.prod.conf root@<host>:/opt/chameleon/nginx.conf` 后重启 web 容器 |

该文件请保持原样，不要在仓库副本里加注释——否则与服务器哈希不再一致，重建时无法用 `sha256sum` 校验。
