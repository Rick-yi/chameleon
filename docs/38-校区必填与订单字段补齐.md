# 校区必填与订单字段补齐

## 一、背景

生产试用反馈里，财务出现“未分配校区”，同时订单列表看不出订单号、收款时间、优惠、经办人和备注：

- P1-04 / P1-32：学员建档、报名下单没有强制校区，历史数据也没有回填，财务只能把空校区单独归为“未分配校区”。
- P1-27：订单列表只有学员、课包、应收、实收、渠道、下单时间、状态，无法核对订单号、收款时间和经办人；线下收款弹窗填写的备注没有落库。

本次把“新数据不再产生空校区”和“订单关键字段可见”两件事一起处理。

## 二、后端改动

### 1. 学员校区兜底与必填

`StudentServiceImpl`：

- 新增 `resolveDefaultCampusId()`：按组织树收集 `DEPT` / `CAMPUS`，优先返回当前账号可见校区，否则返回机构第一个校区。
- `add`：请求未传 `campusId` 时自动兜底；机构没有任何校区时抛出“请选择校区”，不再写入空校区。
- `edit`：老学员编辑时如果校区为空，也按同样规则补齐。
- 该方法同时暴露到 `StudentService`，供订单模块复用。

`StudentOrderServiceImpl.add`：

- 订单校区优先取学员校区；学员为空时调用 `resolveDefaultCampusId()` 兜底。
- 两者都为空时拒绝下单，提示“学员【xxx】未设置校区，请先在学员档案中选择校区”。

### 2. 启动时历史数据回填

`P0SchemaMigration` 增加幂等回填，每次启动执行，已补齐的数据不会重复处理：

1. `STUDENT.CAMPUS_ID`：优先取学员在读班级的校区；单校区机构把空校区、以及指向公司根节点等非校区组织的值统一落到唯一校区；多校区机构留空待人工补录。
2. `STUDENT_ORDER.CAMPUS_ID`：空值或指向公司根节点的历史订单，按学员当前校区纠正。
3. `FIN_DAILY_STAT.CAMPUS_ID`：仅当租户只有一个校区时回填；多校区机构不猜，避免把收入串到错误校区。

同时新增 `STUDENT_ORDER.REMARK` 列，用于保存线下收款备注。

### 3. 订单列表信息

- `StudentOrder` 增加非数据库字段 `operatorName`，列表查询时按 `UPDATE_USER`（没有则 `CREATE_USER`）批量解析用户姓名。
- 关键词搜索除了姓名/家长手机，也支持订单号精确匹配。
- 线下收款 `offlinePay` 现在会把备注写入订单；支付回调与续费仍可传空备注。
- 订单 `remark` 只在下单后收款时写入，不改变原有支付幂等逻辑。

## 三、前端改动

### 学员列表/新增

- 筛选栏新增“校区”下拉，学员分页接口原本已支持 `campusId`，现在可以从界面使用。
- 新增/编辑学员弹窗增加“校区”必填项，只有一个校区时自动选中。
- 手机端学员卡片显示所属校区。

### 报名流程

`EnrollmentFlow` 的校区从“默认当前校区、可清空”改为必选，避免工作台快速报名再次产生空校区。已有学员报名仍沿用学员档案上的校区。

### 订单列表

新增列：

| 列 | 说明 |
|---|---|
| 订单号 | 完整订单号，等宽字体，可一键复制 |
| 收款时间 | 未收款显示 `-` |
| 优惠 | 仅已支付/已退费订单显示“应收 - 实收”，待支付订单不把未收金额误显示为优惠 |
| 经办人 | 最后操作人，未更新过则显示下单人 |
| 备注 | 线下收款时填写的备注，超长省略并在悬停时显示全文 |

表格增加横向滚动，避免列变多后在窄屏挤压。
