# 25 · 工作台快速录入学员

> 前台接待最常见的动作是「家长带孩子来咨询 → 当场建档 → 选课包 → 收款」。
> 原先要跑「学员管理 → 新增学员 → 报名 → 收款台」四步，现在工作台一个流程完成。

---

## 一、入口

- 工作台页头新增主按钮「录入学员」；
- 快捷入口第一项新增「录入学员」（橙色图标），点击直接打开弹窗；
- 两个入口都按 `/student/add` 权限控制，没有权限不显示。

## 二、交互流程

参考前台收银类产品，报名拆成三步，避免一屏塞满字段：

```
填写信息  →  确认收款  →  报名成功
  (form)      (confirm)     (success)
```

1. **填写信息**：学员、家长、课包、班级、实收金额一屏完成；
2. **下一步**：展示学员、课包、班级、应收 / 优惠 / 实收，选收款方式并确认；
3. **成功后**：展示「继续录入」「查看学员」，方便连续接待下一位家长。

只有「选课包 + 立即收款」才走三步；只建档或只生成待收款订单时，直接在当前页保存并提示。

手机端（≤576px）弹窗变成全屏页面：标题栏吸顶、表单独立滚动、底部按钮固定在安全区上方，操作路径与原生 App 一致；桌面端保持 720px 居中弹窗。

## 三、字段

### 学员信息

| 字段 | 必填 | 说明 |
|---|---|---|
| 学员姓名 | 是 | |
| 性别 | 否 | 男/女，默认男 |
| 生日 | 否 | 日期选择 |
| 校区 | 否 | 默认当前用户所属校区；多校区可选 |

### 家长信息

| 字段 | 必填 | 说明 |
|---|---|---|
| 家长姓名 | 否 | |
| 家长手机 | 是 | 11 位手机号校验，用于联系与续费 |

### 报名与收款

| 字段 | 说明 |
|---|---|
| 报名课包 | 选填；不选则只建档，不生成订单 |
| 报读班级 | 选填；按课包所属课程过滤班级，报名成功后批量入班 |
| 立即收款 | 选课包后默认开启；关闭则只生成待收款订单 |
| 应收金额 | 课包价格，只读 |
| 实收金额 | 默认课包价格，可改（优惠/补差）；有零头时出现「抹零」快捷操作 |
| 备注 | 选填，记录意向、优惠说明等 |

确认页展示应收、优惠（应收 - 实收）、实收，以及收款方式、经办人、收款时间和收款备注。

## 四、后端流程

新增 `POST /student/quickEnroll`，一个事务内完成：

1. 创建学员档案（复用 `StudentService.add`，含套餐学员数上限校验）；
2. 选择课包时创建订单（复用 `StudentOrderService.add`）；
3. 开启立即收款时登记收款（复用 `StudentOrderService.offlinePay`，生成课时账户与入账流水）；
4. 任一步失败整体回滚，不会出现「学员建了、订单没建」的半成品。

分班是报名成功后的独立动作（`/course/classStudent/add`）：失败只提示去班级管理手动添加，不影响已完成的建档与收款。

接口权限：方法上校验 `/student/add`；路径加入业务接口白名单，避免为每个租户单独补授权。

收款渠道放开到 `CASH / OFFLINE / WECHAT / ALIPAY`（均为手工登记，线上自动支付仍未接入），订单页、学员详情、移动端收款台的下拉选项同步补齐。

## 五、验证

| 场景 | 结果 |
|---|---|
| 建档 + 课包 + 微信收款 | 订单 `PAID`、渠道 `WECHAT`、实收 3600、课时账户 +22（含赠课 2），确认页展示正确 |
| 实收改为 3599.5 后抹零 | 实收 3599，优惠 1 元，订单按 3599 入账 |
| 选择报读班级 | 报名成功后学员出现在该班学员列表 |
| 建档 + 课包 + 不收款 | 生成 `UNPAID` 订单，出现在工作台「待收款订单」 |
| 只建档不选课包 | 只创建学员，不产生订单 |
| 未选课包却开启收款 | 前端不出现收款字段；后端拒绝：「请选择课包后再登记收款」 |
| 手机端 | 全屏表单、底部按钮固定，可正常完成三步流程 |
| 成功页「查看学员」 | 跳转学员管理并自动打开该学员详情（课时账户已生成） |
