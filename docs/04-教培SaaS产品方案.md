# 04 · 教培 SaaS 产品方案（类校如云）

> 定位：基于 chameleon（Snowy v3.6.5 底座）自研一套**校外培训机构经营管理 SaaS**，自己运营。
> 参考对象：校如云（kkke.cn）—— 招生营销 / 学员管理 / 排课课表 / 扣课消课 / 家校互动 / 续费预警 / 财务分析 / 多校区。
> 状态：方向已确认（教培机构版 + 多租户 SaaS），本文件为模块划分、数据模型与开发排期的蓝图，落地时按里程碑推进。

---

## 一、产品定位与角色

**一句话**：给中小教培机构（艺术/舞蹈/体育/音乐/早教/编程/课外辅导）提供"招生 → 报名 → 排课 → 上课消课 → 续费"全流程经营管理工具，同时给家长一个微信小程序查看课表、消课记录、请假与接收通知。

三个端、三类角色：

| 端 | 使用者 | 说明 |
|---|---|---|
| 平台端（Web） | SaaS 运营方 | 租户开通/套餐/计费/统计/停用（新插件 `snowy-plugin-platform`） |
| 机构端（Web） | 校长 / 教务 / 教师 / 前台财务 | 每个租户一套独立的后台（复用 Snowy 全部 RBAC 能力） |
| 家长端（微信小程序） | 家长 | 绑定学员，查课表/消课/请假/作业/接收通知 |

## 二、总体架构

```
                     ┌────────────────────────────────────────┐
  平台运营方(Web)     │  snowy-plugin-platform   租户/套餐/计费  │
  机构校长/教务/教师  │  snowy-plugin-crm        招生营销        │
  前台/财务 (Web)     │  snowy-plugin-course     课程/课包/排课   │
                     │  snowy-plugin-student    学员/课时账务    │
                     │  snowy-plugin-finance    财务与报表      │
                     │  ────────────────────────────────────  │
                     │  Snowy 底座：sys(权限) auth dev(文件/短信/ │
                     │  定时任务/推送) gen(生成器) biz client     │
                     └───────────────┬────────────────────────┘
                                     │  REST /api（Sa-Token 鉴权 + 租户上下文）
                     ┌───────────────┴────────────────────────┐
                     │  家长微信小程序（uni-app，独立工程）        │
                     │  通知：小程序订阅消息 / 公众号模板 / 短信    │
                     └────────────────────────────────────────┘
```

**关键机制**：

1. **多租户 = 共享库共享表 + `tenant_id` 行级隔离**（SaaS v1 标准做法，成本最低、运维简单）。
   落地：MyBatis-Plus `TenantLineInnerInterceptor` 注册进现有 `GlobalConfigure.mybatisPlusInterceptor()`（当前只有分页拦截器，直接追加即可），自动给所有业务 SQL 追加 `tenant_id` 条件。
2. **租户上下文**：登录时确定租户（账号绑定唯一机构则自动；多机构账号在登录页选择），存入请求级 ThreadLocal；`TenantLineHandler` 从该上下文取租户值。
3. **平台级表不进租户隔离**（见 §三 忽略清单），租户模板数据在开通时初始化。

## 三、多租户改造（关键路径，M0 先行）

### 3.1 表结构约定

- 所有机构侧业务表新增 `tenant_id`（`varchar(20)`，与全工程主键约定一致，带索引），MyBatis-Plus 实体加 `tenantId` 字段；
- 平台侧表（租户表、套餐表）**不加** `tenant_id`，并注册进拦截器忽略清单；
- 需要平台级共享的字典/配置：`tenant_id = 0` 表示平台级（拦截器对 `tenant_id=0` 不拦或按忽略规则处理）。

### 3.2 拦截器配置要点

```
GlobalConfigure.mybatisPlusInterceptor() 追加：
  TenantLineInnerInterceptor(
    handler = 从请求级 ThreadLocal 取 tenantId；
    ignoreTables = [SYS_USER? 见下, T_TENANT, T_TENANT_PACKAGE, ...]（平台表）
  )
```

注意：
- `SYS_USER` 建议**加租户字段**（教职工归属租户），平台超管另用平台角色或 `tenant_id=0`；
- Snowy 有大量 `mapper/*.xml` 手写 SQL —— TenantLine 只能改写 MyBatis-Plus 自动生成的 SQL，**XML 中的手写 SQL 需人工补 `tenant_id` 条件**（改造时逐个核查，这是主要工作量）；
- 复杂 SQL（多表 join、批量 insert）解析失败时走忽略或手写条件，勿硬塞给拦截器。

### 3.3 租户生命周期

| 阶段 | 动作 |
|---|---|
| 开通 | 平台端创建租户 → 生成 `T_TENANT` 记录 + 模板初始化（角色、菜单授权、默认字典、默认配置、`SNOWY_SYS_NAME`） |
| 使用 | 机构账号登录 → 租户上下文 → 全链路隔离 |
| 续费/停用 | 套餐到期检查（定时任务）→ 停用租户（登录拦截 + 会话失效）→ 续费恢复 |

### 3.4 周边系统隔离

- **缓存**：业务缓存 Redis key 统一加租户前缀；easy-trans 字典缓存按租户隔离；
- **文件**：x-file-storage 按 `tenant_id` 分目录；
- **定时任务**：`DEV_JOB` 任务定义归属租户，执行时注入对应租户上下文（续费预警、上课提醒）；
- **Sa-Token 会话**：token 本身无需改造（会话内已绑定用户 → 用户归属租户），登录时校验租户状态。

## 四、模块划分与插件落位

沿用工程插件机制：每个业务插件配一个 `-api` 契约模块，实现放在插件内，登记到根 `pom.xml`、`snowy-plugin/pom.xml`、`snowy-web-app/pom.xml`，包名保持 `vip.xiaonuo`。

| 新插件（模块） | 职责 | 核心页面/功能 |
|---|---|---|
| `snowy-plugin-platform`（+`-api`） | SaaS 运营：租户/套餐/计费/统计/停用 | 租户列表、开通向导、套餐管理、平台看板 |
| `snowy-plugin-crm`（+`-api`） | 招生营销 | 线索管理、跟进记录、试听预约、转化统计 |
| `snowy-plugin-course`（+`-api`） | 课程体系与排课 | 课程、课包（课时数/价格）、班级、排课课表、调课、冲突检测 |
| `snowy-plugin-student`（+`-api`） | 学员与课时账务 | 学员档案、报名订单、课时账户、消课流水、退费、续费预警 |
| `snowy-plugin-finance`（+`-api`） | 财务与报表 | 收款单、退费单、课时耗用报表、经营分析（easyexcel 导出） |

**复用 Snowy 既有能力**（不用重造）：

| 需求 | 复用点 |
|---|---|
| 机构/校区层级 | `SYS_ORG`：总部 → 校区（租户内机构树） |
| 教职工账号与权限 | `SYS_USER` + 角色/菜单/按钮授权 + 机构数据范围 |
| 课程类型等枚举字典 | `SYS_DICT`（租户级字典） |
| 附件/证件上传 | `DEV_FILE`（x-file-storage） |
| 短信通知 | `DEV_SMS`（sms4j） |
| 定时任务（续费预警/上课提醒/套餐到期） | `DEV_JOB`（hutool-cron + CommonTimerTaskRunner） |
| 通知公告 | `SYS_NOTICE`（机构内部） |
| 家长 C 端账号 | `CLIENT_USER`（client 插件）+ 绑定学员 |
| 业务模块脚手架 | gen 代码生成器（每个新模块先用它生成 CRUD 再改） |
| 后端接口文档 | Knife4j（按插件分组自动扫描） |

**家长端小程序**：独立工程（建议 uni-app，一套代码发微信小程序 + H5），调各插件提供的 C 端 API（契约放对应 `-api`）。

## 五、角色与权限

| 角色 | 归属 | 权限范围 |
|---|---|---|
| 平台超管 | 平台 | 租户管理、套餐、平台统计（platform 插件菜单） |
| 校长 | 机构 | 全机构菜单（含财务、报表） |
| 教务 | 机构 | 学员、课程、排课、课时账务 |
| 教师 | 机构 | 班级课表、点名/消课确认、作业布置、家校互动 |
| 前台/财务 | 机构 | 报名、收款、退费 |
| 家长 | 小程序 | 仅本学员数据（C 端授权 + 学员绑定关系控制） |

实现：机构内沿用 Snowy 角色-资源授权；家长侧不走 SYS_USER，走 CLIENT_USER + `parent_student` 绑定表，接口层校验绑定关系。

## 六、核心数据模型

> 命名沿用 Snowy 大写风格（`SYS_USER` 式）；平台表用 `T_` 前缀区分。只列关键字段，落地时用 gen 生成器出全字段。

### 平台域（无租户隔离）

| 表 | 关键字段 |
|---|---|
| `T_TENANT` | 机构名称、联系人、手机、套餐 id、到期时间、状态（试用/正常/停用）、开通时间 |
| `T_TENANT_PACKAGE` | 套餐名、价格、有效期、功能开关（JSON）、学员数上限、校区数上限 |

### 招生域（租户隔离）

| 表 | 关键字段 |
|---|---|
| `CRM_LEAD` 线索 | 学员姓名、家长手机、意向课程、来源渠道、状态（新线索/已跟进/已试听/已报名/流失）、跟进人 |
| `CRM_LEAD_FOLLOW` 跟进记录 | 线索 id、跟进方式、内容、下次跟进时间 |
| `CRM_TRIAL_APPOINTMENT` 试听预约 | 线索 id、课程 id、试听时间、状态、结果 |

### 课程域（租户隔离）

| 表 | 关键字段 |
|---|---|
| `COURSE_CATEGORY` 课程大类 | 名称、父级（如 美术/舞蹈/编程） |
| `COURSE` 课程 | 名称、大类、适用年龄、班型（一对一/小班/大班）、单价口径、每课扣课时数、请假/缺勤是否扣课 |
| `COURSE_PACKAGE` 课包 | 课程 id、课时数、赠课时数、价格、有效期、状态 |
| `COURSE_CLASS` 班级 | 课程 id、名称、上课校区、上课时段模板、教师、容量、状态 |
| `COURSE_CLASS_STUDENT` 班级学员 | 班级 id、学员 id、入班时间、状态（在学/退班） |
| `COURSE_SCHEDULE` 排课 | 班级 id、日期、开始/结束时间、教室、教师、状态（正常/已调/已取消） |
| `COURSE_SCHEDULE_CHANGE` 调课记录 | 原排课 id、原因、新时间、操作人 |
| `COURSE_CLASS_ATTEND` 上课点名 | 排课 id、学员 id、出勤状态（到课/请假/缺勤）、扣课标记 |

### 学员与课时域（租户隔离，业务命脉）

| 表 | 关键字段 |
|---|---|
| `STUDENT` 学员 | 姓名、性别、生日、家长姓名、家长手机、校区、报读课程、状态、来源线索 id |
| `STUDENT_PARENT_BIND` 家长绑定 | 学员 id、家长 C 端用户 id、关系 |
| `STUDENT_ORDER` 报名订单 | 学员 id、课包 id、订单金额、实收金额、支付方式、状态（待支付/已支付/已退费）、操作人 |
| `STUDENT_LESSON_ACCOUNT` 课时账户 | 学员 id、课程 id、总课时、已扣课时、剩余课时、状态 |
| `STUDENT_LESSON_CONSUME` 消课流水 | 学员 id、排课 id、扣课时数、类型（上课扣课/请假补课/人工调整）、操作人、时间 |
| `STUDENT_REFUND` 退费单 | 订单 id、退费金额、剩余课时折算、审批人、状态 |
| `STUDENT_RENEW_WARN` 续费预警 | 学员 id、剩余课时、预警阈值、提醒状态（由定时任务生成） |

### 家校域（租户隔离）

| 表 | 关键字段 |
|---|---|
| `HOME_LEAVE_REQUEST` 请假 | 学员 id、排课/日期、原因、审批状态 |
| `HOME_HOMEWORK` 作业 | 班级 id、内容、附件、截止时间、提交列表 |
| `HOME_COMMENT` 师生互评 | 排课 id、评价方、内容、星级 |
| `NOTIFY_LOG` 通知流水 | 接收人（家长端）、渠道（小程序订阅消息/公众号/短信）、模板、内容、发送状态 |

### 财务域（租户隔离）

| 表 | 关键字段 |
|---|---|
| `FIN_PAYMENT` 收款单 | 订单 id、金额、渠道（微信/支付宝/现金）、收款人、时间、关联流水号 |
| `FIN_STATEMENT` 对账/报表 | 由 FIN_PAYMENT + 消课流水汇总生成（日/月/课程/校区维度） |

## 七、C 端与消息推送

- **小程序**：uni-app 工程（微信小程序首发，可扩展 H5/抖音）；页面：绑定学员、课程课表、消课记录、课时剩余、请假、作业、通知中心。
- **推送渠道抽象**：新增统一 `NotifyChannel` SPI（仿 CommonTimerTaskRunner 模式），首期实现：
  - 小程序订阅消息（微信模板，需在公众平台申请模板；一次性订阅 → 每次操作请求授权）；
  - 短信（复用 DEV_SMS）；
  - 公众号模板消息（可选，二期）。
- **触发点**：上课提醒（排课生成/前一天定时任务）、消课通知（点名后实时）、续费预警、调课通知、活动通知。

## 八、SaaS 运营能力（平台端）

- 租户开通向导：创建租户 → 选套餐 → 初始化模板数据 → 生成管理员账号；
- 套餐管理：功能开关、学员数/校区数上限、价格、试用期；
- 到期处理：定时任务扫描 → 提前提醒（通知机构管理员）→ 到期停用 → 续费恢复；
- 平台统计：租户数、活跃租户、各套餐占比、机构经营规模分布；
- **支付**：微信支付（机构端收款 + 平台端套餐购买），需企业主体 + 微信支付商户号；
- **合规提醒**：对外运营收费需 ICP 备案（参照校如云蜀ICP备）、增值电信业务许可证（EDI），上线前办理。

## 九、开发里程碑与排期

> 单人全职估算（天），按里程碑验收；团队可并行压缩。标注 ★ 为核心价值闭环。

| 里程碑 | 内容 | 估时 | 验收标准 |
|---|---|---|---|
| **M0 多租户地基** ★ | T_TENANT 等平台表、TenantLine 拦截器 + 忽略清单、XML 手写 SQL 核查补条件、登录绑定租户、租户模板初始化、平台端租户管理页 | 10-15 天 | 两个租户数据完全隔离；开通向导可用 |
| M1 基础域 | 校区/教职工（主要复用）、学员档案 CRUD（gen 生成）、班级学员绑定 | 5-7 天 | 学员/班级页面可操作 |
| **M2 课程域** ★ | 课程/课包/班级、排课与课表、调课、点名扣课联动 | 10-14 天 | 排课→课表→点名全流程 |
| **M3 课时账务** ★ | 报名订单、课时账户、消课流水、退费、续费预警定时任务 | 8-12 天 | 报名→扣课→余额/预警闭环；流水可追溯 |
| M4 家校端 ★ | 小程序框架、家长绑定、课表/消课/请假/作业、订阅消息推送 | 10-14 天 | 家长端全流程 + 通知送达 |
| M5 财务报表 | 收款单、退费单、课时耗用报表、经营分析、easyexcel 导出 | 5-8 天 | 报表数字与流水一致 |
| M6 SaaS 运营完善 | 套餐计费、到期停用恢复、平台统计、微信支付对接 | 6-10 天 | 收费闭环可用 |
| 收尾 | 安全加固（弱口令已内置）、压测、备案、生产部署（docker-compose 修好 build 段） | 5 天 | 上线 |

**合计约 2.5-4 个月（单人）**。建议顺序：M0 → M1 → M2 → M3（先跑通核心闭环）→ M4（家长端）→ M5 → M6；gen 代码生成器全程参与，业务规则集中在 Service 层，前端页面用现有 admin-web 组件库。

## 十、风险清单与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| TenantLine 拦不住 XML 手写 SQL → 租户串数据 | 严重 | M0 逐文件核查 `mapper/*.xml`，统一补 `tenant_id` 条件；联调时用双租户回归用例 |
| 忽略清单漏配平台表 | 严重 | 清单集中管理 + 注释说明每张表归属 |
| 多机构账号登录体验 | 中 | 登录页机构选择（记住最近一次） |
| 订阅消息一次性授权 | 中 | 在关键操作时主动请求授权；配合短信兜底 |
| 微信支付/小程序资质 | 高（流程性） | 尽早用企业主体注册小程序 + 支付商户号 |
| 备案与 EDI 许可 | 高（流程性） | 上线前 2 个月启动 |
| Snowy 数据范围与租户条件叠加 | 中 | 租户条件先于机构数据范围生效，权限语义 = 租户 ∩ 机构范围 |

## 十一、待确认决策（影响后续落地）

1. **计费模式**：免费试用 → 按月/年订阅？按机构规模分档？
2. **小程序技术栈**：uni-app（推荐，可复用 H5）还是原生小程序？
3. **支付**：机构端收款是否必须微信支付（vs 只做线下收款登记，二期再接支付）？
4. **自助注册**：对外开放自助注册开通，还是销售/运营手动开通（M0 先做手动，自助放二期）？
