# 退费原因与试算

> 日期：2026-10-27

## 一、问题

退费申请时的原因原来临时写进 `OPINION`，审批时又被审批意见覆盖，审批人看不到申请原因。PC 申请退费时也只显示订单，不显示可退多少课时、赠课作废多少、预计退多少钱。

## 二、处理

### 1. 原因独立落库

- `STUDENT_REFUND` 新增 `APPLY_REMARK` 字段；
- 新申请原因写入 `APPLY_REMARK`，审批意见继续写 `OPINION`，两者互不覆盖；
- 启动迁移把旧的待审批单 `OPINION` 复制到 `APPLY_REMARK`，并清空待审批单的 `OPINION`，避免同一条原因显示两遍；
- 退费原因改为必填（前端表单 + 后端 `@NotBlank`）。

### 2. 退费试算

新增 `GET /student/refund/preview?orderId=...`，返回：

- 学员、课包；
- 课包正课/赠课、已消耗课时；
- 可退正课、随订单作废的赠课；
- 实付金额、折算单价、预计退款；
- 是否可退、是否已有在途退费单。

口径与真正提交退费一致：可退正课 = 课包购买课时 - 已消耗（先进先出），赠课不可退，折算单价 = 实付 / 课包购买课时。

### 3. 页面

PC 退费申请弹窗：

- 打开后自动试算并展示明细；
- 已有在途退费单或课时已消耗完时，禁止提交并说明原因；
- 退费列表新增「申请原因」列。

PC 退费审批弹窗：

- 展示学员、可退课时、预计退款和申请原因；
- 审批意见独立输入，不再覆盖申请原因。

APP 退费卡：

- 分别展示「申请原因」和「审批意见」。

### 4. 权限

新增 `/student/refund/preview` 按钮资源和接口权限，自动授权给已有 `/student/refund/apply` 权限的角色。

## 三、验证

- 后端 Maven 构建通过；
- 前端构建通过（5418 个模块）；
- 本地数据库启动迁移成功添加 `STUDENT_REFUND.APPLY_REMARK`；
- 试算接口返回：可退 20 正课、赠课作废 2、实付 3600、预计退款 3600；
- 提交退费原因「自动化试算验证」后，`APPLY_REMARK` 落库，`OPINION` 为空；
- 撤销并清理测试退费单后，订单仍为 `PAID`，课时账户仍为 `NORMAL`；
- PC 实测退费申请弹窗展示试算明细，退费列表展示申请原因；
- APP 390px 实测退费卡展示申请原因；
- 无前端运行异常。

## 四、边界

- 试算是申请时快照；审批时会按最新消耗重算，避免申请后继续上课导致金额不一致。
- 历史已审批/已退款单没有独立的申请原因，仍以原 `OPINION` 为准。
- 本次不发布生产。
