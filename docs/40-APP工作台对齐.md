# APP 工作台与前端对齐

## 一、目标

APP 首页原来按“教学 / 招生 / 前台”三个视角各展示 4 个指标和一个待办列表，与 PC 工作台的数据口径、待办类型和行内动作不一致。

本次把 APP 首页改成移动版工作台：

- 数据口径与 PC 工作台一致；
- 待办类型与 PC 工作台一致；
- 能在 APP 内直接完成收款、退费审批、线索跟进、录入学员、学员报名/续费；
- 保留移动端按角色收敛：教学、招生、前台只看到自己该看的指标和入口。

## 二、APP 首页现在有什么

### 1. 关键指标

经营总览（all）与 PC 工作台一致：

- 今日收款
- 本月收款
- 待收款订单
- 在读学员
- 今日应到
- 已点名
- 未点名课节
- 点名进度

按视角裁剪：

| 视角 | 指标 |
|---|---|
| 教学 | 在读学员、今日应到、已点名、未点名课节、点名进度 |
| 招生 | 在跟线索、新线索、待收款、今日收款 |
| 前台财务 | 今日收款、本月收款、待收款、待审批退费 |

### 2. 待办卡片

与 PC 工作台同结构，最多展示 5 条，可点「全部」进入对应列表：

- 待收款订单：显示逾期天数，行内「收款」
- 今日课节：显示时间/教室/老师/应到/已点，行内「去点名」
- 待审批退费：显示可退课时/金额/逾期天数，行内「审批」
- 待跟进线索：显示手机号/跟进人/逾期或今日跟进，行内「跟进」
- 续费预警：显示原因和剩余课时，行内「处理」
- 今日收款：显示学员/课包/实收/时间

### 3. 快捷操作

- 录入学员：APP 内直接打开三步报名流程（建档 + 课包 + 收款）
- 报名购课：进入学员名册，每个学员卡片有「报名」
- 收款台、我的课表、点名消课、招生线索、经营看板

## 三、新增页面与直达链路

### 新增 `/app/student/renew`

- 待处理 / 已续费 / 已忽略三个页签；
- 显示课程、剩余课时、预警原因、最近提醒时间；
- 「立即扫描」按权限显示；
- 「续费」复用 `EnrollmentFlow` 已有学员模式，选课包并收款后课时入账，预警自动标记续费；
- 「忽略」直接标记忽略。

### 工作台行内动作

| 动作 | 跳转 | 行为 |
|---|---|---|
| 收款 | `/app/cashier/orders?status=UNPAID&orderId=...` | 收款台加载后自动打开对应订单的收款弹窗 |
| 审批 | `/app/cashier/orders?tab=refund&refundId=...` | 自动打开退费确认，确认后同意并冻结课时账户 |
| 跟进 | `/app/enroll/lead?id=...&action=follow` | 线索详情加载后自动打开「写跟进」 |
| 去点名 | `/app/teach/attend?scheduleId=...&classId=...` | 进入点名页 |
| 处理续费 | `/app/student/renew` | 进入续费预警页 |

### 学员报名

`/app/teach/students` 每个学员卡片新增「报名」：

- 复用 `EnrollmentFlow` 已有学员模式；
- 只选课包/班级/金额/渠道，不再重复填学员和家长信息；
- 成功后刷新名册。

## 四、一并修复的问题

- **线索详情双重解包**：`leadDetail` 已被请求拦截器解包，页面却又取 `.data`，导致详情为空；已改为直接使用返回值。
- **线索转学员双重解包**：`studentAdd` 返回学员 id，页面取 `.data` 导致订单学员 id 为 undefined；已修正。
- **APP 视角路径判断不认 query**：`/app/cashier/orders?status=UNPAID` 这类带参数路径被误判为不可访问；`canVisit` 现在先去掉 query 再匹配。
- **收款弹窗渠道溢出**：390px 下 4 个渠道按钮横向溢出，改为下拉选择。
- **APP 首页标题**：布局页头改为「工作台」，去掉页面内重复标题。

## 六、边界

- APP 仍是角色视角裁剪，不会让老师看到全机构财务；PC 工作台是管理员视角，这是有意的差异。
- 移动端不做 PC 的批量操作、表格列设置和全局校区切换。
- 续费/报名复用现有 `EnrollmentFlow`，没有另做一套移动端收银逻辑。
- 本文档只记录代码与本地验证，生产发布仍需明确指令。
