# 28 · 平台租户运营闭环

> 对应问题清单 docs/26 的 P0-03：平台端原来只有“编辑/删除”，续费、停用、重置密码、登录记录都做不了。
> 这一批让平台运营不连数据库就能完成“开通 → 试用 → 续费 → 停用 → 恢复 → 重置密码”。

---

## 一、租户续费

- 入口：租户列表行内「续费」。
- 表单：续费天数（1～3650 天，提供 1/3/6/12 个月快捷项）、续费套餐（可选，默认沿用）、金额、备注。
- 规则：
  - 未过期从原到期日顺延，已过期从当天起算；
  - 续费后状态自动置为 `NORMAL`；
  - 变更套餐时同步刷新租户能力缓存（限额与功能开关）。
- 留痕：写入 `T_TENANT_RENEW`（天数、金额、原/新到期时间、操作人、备注），列表行内「更多 → 续费记录」可查。

## 二、停用 / 启用

- 入口：租户列表行内「停用」或「启用」。
- 停用必须填写原因，二次确认后：
  - 租户状态置为 `STOP`；
  - 原因、时间、操作人写入租户 `EXT_JSON`；
  - 立即踢出该租户全部用户的 B 端会话（按 `SYS_USER.TENANT_ID` 批量 `logout`）。
- 启用后恢复 `NORMAL`，重新登录即可使用。
- 登录侧提示已区分原因：机构不存在、已停用、已于某日到期，并提示联系平台运营。

## 三、重置管理员密码

- 入口：租户列表行内「更多 → 重置管理员密码」。
- 生成 12 位随机一次性密码，立即踢出该管理员全部会话；**密码只在本次响应展示一次**，弹窗提供复制。
- 选择账号的顺序：优先 `admin`，没有则取该租户最早创建的用户。
- 审计：租户 `EXT_JSON` 记录重置时间与操作人；操作日志中的参数和返回值统一脱敏（字段名包含 `password` 一律替换为 `******`）。

## 四、登录与续费记录

- 「更多 → 登录记录」：最近 20 条账号与登录时间（数据来自 `T_TENANT_LOGIN`）。
- 「更多 → 续费记录」：最近 20 条续费明细。
- 时间统一格式化为 `yyyy-MM-dd HH:mm:ss`，避免前端显示 ISO 字符串。

## 五、开通租户校验

- 联系人与联系电话改为必填，电话校验 11 位手机号，避免开通后联系不上客户。

## 六、验证记录

| 场景 | 结果 |
|---|---|
| 续费 90 天、金额 1000 | 到期日顺延至 2028-01-20，状态由 TRIAL 变 NORMAL，续费记录含操作人 |
| 停用示例机构 | 状态 STOP，`EXT_JSON` 记录原因/时间/操作人，日志显示踢出 6 个会话 |
| 停用后登录 | 提示「机构已停用，请联系平台运营」，不会进入系统 |
| 启用后登录 | 使用重置后的新密码登录成功 |
| 重置管理员密码 | 返回账号与 12 位新密码；旧密码失效；审计日志中密码已脱敏 |
| 登录记录 | 返回最近 20 条，时间格式正常 |
| 续费记录 | 返回天数、金额、原/新到期、操作人、备注 |

## 七、已知边界

- 一次性密码目前未强制首登修改，后续可在用户信息中增加 `mustChangePassword` 标记并在路由守卫拦截。
- 续费金额只做记录，尚未接入账单/发票；到期前 30/7/1 天提醒可复用现有定时任务继续扩展。
