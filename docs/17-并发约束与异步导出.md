# 17 · 并发约束、移动端消息中心与通用异步导出

> 这一轮不再加新业务，只补三处「数据会错、体验会断、大数据会超时」的地方。

---

## 一、排课并发约束

### 原来会怎样

排课是「先查冲突、再插入」，两步之间没有锁：

- 两个教务同时给同一个班排同一时段，两边都能查不到冲突，然后都插入成功；
- 教师、教室的跨班冲突虽然也会查，但同样存在并发窗口。

压测数据集里就已经留下了 2200 条重复课节（同一班级、同一天、同一开始时间各 12 条）。

### 现在怎么做

**数据库层兜底**：`COURSE_SCHEDULE` 增加生成列 `ACTIVE_SLOT_KEY`：

```sql
CASE WHEN STATUS = 'NORMAL' AND CLASS_ID IS NOT NULL
     THEN CONCAT(CLASS_ID, '|', DATE_FORMAT(SCHEDULE_DATE, '%Y-%m-%d'), '|', TIME_FORMAT(START_TIME, '%H:%i'))
     ELSE NULL END
```

再对 `(TENANT_ID, ACTIVE_SLOT_KEY)` 建唯一索引。用生成列而不是直接建唯一索引，是为了让**已取消 / 已调课**的课节不参与约束——取消后同一时段仍可重新排课。

迁移脚本在启动时幂等执行（`P0SchemaMigration`）：

1. 先把历史重复数据按「每组保留 ID 最小的一条」置为 `CANCELED`，并打一条 WARN 日志；
2. 再建生成列与唯一索引。

**应用层提示**：`add` / `change` / `generate` / `generateAdhoc` 捕获 `DuplicateKeyException`，转成可读提示（「该班级在 2026-11-03 09:00 已有排课，请刷新后重试」），不会把 500 抛给用户。

**冲突明细**：原来只说「教师同时段已有排课」，现在会带上对象、日期时间和班级：

```
排课存在冲突：教室【B201】在 2026-11-03 09:00-10:30 已被【素描基础 A1】占用；
班级【素描基础 A1】在 2026-11-03 09:00-10:30 已有排课；
教师【王老师】在 2026-11-03 09:00-10:30 已有排课（素描基础 A1）
```

> 仍存在的一个窗口：教师/教室的跨班冲突只有应用层校验，没有数据库约束（一个时段可能被不同班级占用，唯一键无法表达）。多人同时排课时建议加 Redis 锁，或在排课入口做租户级串行化。

## 二、移动端

### 登录失效不再掉回 PC 登录页

`utils/request.js` 原来的 401 处理统一弹 AntD 模态框并 `reload()`，在 WebView 里体验很割裂。现在按路径区分：

- `/app/**`：清 token，直接 `location.replace('/app/login')`，不弹框；
- 其余页面：保持原来的「重新登录」模态框。

### 消息中心

试听自动化、续费预警、未支付提醒都会发站内信，但 App 端原来没有入口。现在：

- 新增两个只查本人的接口（不占用平台权限）：
  - `GET /sys/index/message/page?current=&size=&category=` —— 按接收人分页；
  - `GET /sys/index/message/unreadCount` —— 未读数；
- 新增页面 `/app/message`：列表（未读圆点、时间、摘要）、点击看详情、全部已读、加载更多；
- 「我的」页新增「消息中心」入口并显示未读条数。

PC 端顶栏的消息抽屉继续走原接口，不受影响。

## 三、通用异步导出

### 设计

财务报表早就支持异步导出，但课表、教务报表、招生报表仍是同步全量查询 + 直接写响应，数据量一大就超时。

这一轮把异步导出抽成通用能力：

| 层 | 内容 |
|---|---|
| SPI（`snowy-plugin-biz-api`） | `BizExportBuilder`：`type()` / `title()` / `build(paramJson)`，返回 `List<BizExportSheet>` |
| 任务（`snowy-plugin-biz`） | `BIZ_EXPORT_TASK` 表 + 线程池 + `BizExportTaskService`（创建、执行、过期文件清理） |
| 接口 | `POST /biz/export/async`、`GET /biz/export/status`、`GET /biz/export/download` |
| 前端 | `utils/asyncExport.js`：创建 → 每 1.5 秒轮询 → 成功后自动下载 |

业务模块只要实现一个 Bean，就能复用三个接口。当前已接入：

- `COURSE_ACADEMIC` —— 教务报表（出勤汇总 / 班级满班率 / 教师课时 / 课消进度 / 风险学员）；
- `CRM_REPORT` —— 招生报表（漏斗 / 来源 / 跟进排行）。

`AcademicReportService` 和 `CrmReportService` 都把行构建抽成 `buildSheet(...)`，同步导出与异步导出共用同一份逻辑，不会再出现两边口径不一致。

### 前端用法

```js
import { runAsyncExport } from '@/utils/asyncExport'

runAsyncExport('COURSE_ACADEMIC', { ...buildQuery(), reportType: 'CLASS_FILL' })
```

任务表按租户隔离（已加入 `TENANT_TABLES`），文件保留 3 天，后台生成新任务时顺带清理过期文件。
