# 32 · 手机点名体验改造

> 对应 UI/UX 审计中选定的最深切口：老师在手机上给一个班点名。
> 真实问题：390px 下「确认点名并扣课」右边缘在 454px，超出屏幕 64px；按钮 32px、输入 14px、白字/果子绿对比度 2.49:1。

---

## 一、改造内容

### 1. 主操作不再被裁切

- 操作区从 `a-space`（nowrap）改为 CSS Grid：桌面一行右对齐，手机 3 列 + 确认按钮独占一行。
- 手机端确认按钮全宽、46px 高、字号 15px，显示待提交人数。
- 375 / 390 / 414 / 768 实测均完整可见，无横向溢出。

### 2. 手机筛选区与课节卡片

- 日期、班级改为两列网格，刷新按钮独占一行，避免挤在一行。
- 课节卡片在手机端改为横向滚动 + snap，一屏内可切换多个课节，减少纵向滚动。
- 日期/班级输入字号提升到 16px，避免 iOS 聚焦自动放大。

### 3. 触控尺寸

- 手机端所有按钮高度统一 44px。
- 「换一节」提升到 44px 点击区；「撤销」增加内边距。
- 学员方块保持 100px 高，足够单指点击。

### 4. 对比度

- 点名页主按钮保留果子绿 `#4BB964`，文字改为深绿 `#123B2B`，对比度 5.00:1，达到 WCAG AA。
- 禁用态改为浅绿底 + 深绿字，对比度 8.08:1，不再出现“白字几乎看不见”。
- 说明：这是点名页的局部试点；全局主按钮的对比度需要在设计系统层统一决策。

### 5. 失败态

- 课节加载失败、学员名单加载失败分别显示错误提示和「重试」，不再只显示“该日期没有排课”或“应到 0 人”。
- 切换日期/班级时清空旧名单和旧提示。

### 6. 移动端外壳修复

审计 414px 时发现整个后台顶部导航溢出到 691px。原因是 `isMobile` 用 `document.body.clientWidth` 判断，桌面布局先把 body 撑宽后误判为非移动端。

- 初始化改为 `window.innerWidth < 992`；
- resize 监听也改用 `window.innerWidth`。
- 修复后 375 / 390 / 414 / 768 均无横向溢出，1280 桌面布局不受影响。

## 二、实测结果

| 宽度 | 页面横向溢出 | 确认按钮右边缘 | 按钮高度 | 输入字号 |
|---|---|---|---|---|
| 375 | 0 | 339（可见） | 44px | 16px |
| 390 | 0 | 354（可见） | 44px | 16px |
| 414 | 0 | 378（可见） | 44px | 16px |
| 768 | 0 | 完整 | 44px | 16px |
| 1280 | 0 | 完整 | 32px（桌面） | 14px |

对比度：深绿 `#123B2B` / 果子绿 `#4BB964` = 5.00:1；禁用态 = 8.08:1。

## 三、未完成的验证

- 还没有 5 位真实老师的可用性测试、任务耗时和错误率；
- 没有微信内置浏览器和 iOS Safari 实机测试；
- 没有屏幕阅读器/axe 报告；
- 多课节横向滑动的真实触感未在真机验证；
- 全局主按钮的对比度仍未统一，其他页面仍是白字/果子绿。

下一步建议：先找 3–5 位老师按“打开点名 → 全部到课 → 改 1 个缺勤 → 确认”走一遍，记录耗时和误触；通过后再把深色文字的主按钮方案推广到全局设计系统。
