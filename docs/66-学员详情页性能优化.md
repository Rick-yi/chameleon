# 学员详情页性能优化

## 一、原来的三个问题

查看代码发现详情页有三处明显浪费：

**1. 打开就并发拉 10 个请求**

```js
Promise.all([
  studentDetail, lessonAccountPage(50), lessonFlowPage(50), orderPage(50),
  refundPage(50), coursePage(100), studentAttendPage(50),
  studentTimeline, tagList, sundryListByStudent
])
```

其中 `coursePage({size:100})` 只是为了给课程 id 映射名字，却把整个课程列表拉回来；`studentTimeline` 是跨多表聚合（内部 4 次查询、上限 300 条）。用户只看「全部动态」时，其余 9 个请求都是白跑的。

**2. 每个页签固定 50 条、无分页**

6 个表格全是 `:pagination="false"` + `size: 50`。超过 50 条的课时流水、出勤记录**静默看不到**，页面上也没有任何提示。对一个上了两年的学员，流水早就过千条。

**3. 任何操作后全量重拉**

收款、退费、加标签之后都调 `loadAll()`，10 个请求再跑一遍。

## 二、改法

### 懒加载

打开详情只加载「学员基础信息 + 标签」，其余页签在**首次切换时**才加载：

```js
watch(activeTab, (key) => {
  if (key === 'timeline') loadTimeline()
  else if (!tabLoaded[key]) loadTab(key)
})
```

课程名映射也改为按需加载一次（仅课时账户/流水/订单页签需要）。

### 服务端分页

6 个表格改为独立分页状态，默认 10 条，可选 10/20/50，并显示「共 N 条」：

```js
const tabPage = reactive({ account: { current:1, size:10, total:0 }, ... })
```

翻页只重新请求该页签，`total` 用后端返回的总数。

### 操作后定向刷新

`loadAll()` 换成 `refreshAfterAction(tabKeys)`，只刷新受影响的页签：

| 操作 | 刷新范围 |
| --- | --- |
| 线下收款 | 订单 + 课时账户 + 流水 |
| 取消订单 | 订单 |
| 学杂费增/收/退/删 | 学杂费 |
| 课时人工调整 | 账户 + 流水 |
| 退费申请 | 退费单 + 订单 |
| 退费审批 | 退费单 + 账户 |
| 确认退款 | 退费单 + 账户 + 流水 + 订单 |
| 撤销退费 | 退费单 + 账户 |
| 状态变更 / 标签 | 仅基础信息 |

另加一条：时间线是默认页签，若已加载过，操作后一并刷新，保证操作记录能立即看到。

## 三、修掉一个真实缺陷

优化后跑回归报出：

```
[FAIL] 无前端异常 | /student?id=s_ux_001:Uncaught (in promise)
```

原因是 `loadTab` / `loadTimeline` 只有 `.then()` 没有 `.catch()`。页签是切换时自动触发的，接口失败就变成未捕获的 Promise rejection——控制台报错，但用户看不到任何提示。

补上 `.catch` 后给出明确提示，回归转通过。这是分页改造顺带暴露出来的既有隐患。

## 四、实测效果

用 CDP 记录打开详情页期间的真实接口调用：

**打开详情（详情相关）**

| 项目 | 改前 | 改后 |
| --- | --- | --- |
| 详情相关请求 | 10 个 | **3 个**（detail + tagList + timeline） |

其余为应用外壳（登录信息、菜单、字典）与抽屉背后的列表页，与本次无关。

**切到「课时流水」**

新增 2 个调用：

```
/api/course/page?current=1&size=200        ← 课程名映射，一次性
/api/student/lessonFlow/page?current=1&size=10&studentId=s_ux_001
```

分页参数生效（`size=10`），并带总数。
