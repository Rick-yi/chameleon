# 老师管理

## 一、设计

老师不再单独建一套重复的档案表，直接复用系统账号体系：

- 老师 = `SYS_USER` 账号 + `teacher` 角色；
- 账号归属校区通过 `ORG_ID` 关联 `SYS_ORG`；
- 班级、排课继续使用 `TEACHER_ID`，与现有数据兼容。

## 二、页面功能

新增「老师管理」菜单（教务运营 → 老师管理，路径 `/teacher`）：

- 老师列表：姓名、账号、手机、校区、带班数、学员数、状态；
- 新增老师：姓名、登录账号、手机（选填）、所属校区、初始密码（选填）；
- 自动授予「授课老师」角色；班级/排课的老师下拉即可选到；
- 编辑姓名、手机、校区；
- 停用/启用账号；
- 重置为系统默认密码；
- 支持姓名/账号搜索、状态筛选。

带班数和学员数从班级列表汇总，不额外维护冗余统计表。

## 三、账号创建流程

1. 创建系统用户（`/sys/user/add`）；
2. 授权 `teacher` 角色（`/sys/user/grantRole`）；
3. 如果授权失败，自动删除刚创建的无角色账号，避免留下脏数据。

老师账号不强制职位（`POSITION_ID`），解决部分租户没有职位数据时无法建老师的问题。

## 四、班级选老师

`/course/schedule/teacherOptions` 现在优先返回带 `teacher` 角色的用户；为了兼容存量数据，也保留 `superAdmin`（管理员可兼课）。如果租户还没有任何老师角色账号，则退回原来的全量用户选项，避免班级表单直接不可用。

## 五、菜单与权限

- 新增菜单资源 `menu_teacher_001`，挂到教务运营；
- 启动迁移自动授权给所有租户的 `superAdmin`；
- 复用现有 `/sys/user/*` 接口，不新增一套老师 CRUD 权限。

## 六、验证

- 本地老师管理页显示 `teacher01`（王老师），总校区，1 个班、5 名学员；
- 接口新增老师（不传 positionId）成功，授权 teacher 角色后按 `roleCode=teacher` 可查到；
- 老师页操作列（编辑/停用/重置密码）正常显示；
- 前端构建通过；
- 测试账号已删除。

## 七、边界

- 当前老师管理不包含课时费、教师绩效、可授课时间维护；可授课时间仍在排课页维护。
- 老师删除采用账号删除；已排课/已点名历史保留。
- 一个老师可带多个班级，班级与老师仍是一对多关系。
- 生产发布需等明确授权。
