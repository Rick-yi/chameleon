# 30 · 工作台待办闭环

> 对应问题清单 docs/26 的 P1-09 / P1-10 / P1-11 / P1-14：
> 工作台原来只有金额和数量，没有“今天要做什么”；待办只能跳列表，不能直接处理。

---

## 一、今日教学指标

在金额指标下面新增一行教学指标：

| 指标 | 口径 |
|---|---|
| 今日应到 | 今天所有课节的 `studentCount` 之和 |
| 已点名 | 今天所有课节已保存的点名人数 `attendCount` 之和 |
| 未点名课节 | `attendStatus != DONE` 的课节数 |
| 点名进度 | 已点名 / 应到，0～100% |

四个指标都可点击，直接进入课表或点名页。课节列表里“待点名”的排在前面，并显示“应到 X · 已点 Y”。

## 二、逾期提示

- 待收款订单：按创建日期计算，超过 0 天显示红色「逾期 N 天」；
- 待审批退费：同样按申请日期显示「逾期 N 天」；
- 待跟进线索：下次跟进时间早于今天显示「逾期 N 天」，等于今天显示橙色「今日跟进」。

按自然日计算，不按小时，避免早上刚创建的订单就显示逾期。

## 三、待办直达操作

| 待办 | 行内按钮 | 行为 |
|---|---|---|
| 待收款订单 | 收款 | 在工作台直接打开收款弹窗，确认后立即刷新待办，不再跳收款台 |
| 待审批退费 | 审批 | 在工作台直接打开退费审批弹窗，展示申请原因/可退课时/预计退款，通过或驳回后立即刷新 |
| 待跟进线索 | 跟进 | 跳到招生线索并自动打开该线索的跟进弹窗 |

收款与审批不再写入 `sessionStorage`，直接复用工作台内的弹窗和 `order/offlinePay`、`refund/approve` 接口；线索跟进仍沿用 `workbench:action` 跳转。按钮按权限显示（收款 `offlinePay`、审批 `refund/approve`、跟进 `follow/add`），无权限时不出现。

## 四、空态动作

“今日课节”为空时不再只有一句话，提供「去排课」「查看本周课表」两个入口。

## 五、顺手修掉的口径问题

原工作台“今日收款”取的是最近 5 条已支付订单再按支付时间过滤，订单多时会漏；同时财务看板调用的参数名用了 `startDate/endDate`，后端实际接收 `startTime/endTime`，导致日期范围被忽略、“本月收款”和“今日收款”拿到同一份全量汇总。

本轮修正：

- 参数改为 `startTime/endTime`；
- 今日收款改用“当天”财务汇总，列表只用于展示明细；
- 汇总取不到时退回订单列表合计。

验证：本地今日收款从错误的 ¥64,800 恢复为真实的 ¥3,600，本月仍为 ¥64,800。

## 六、验证记录

| 场景 | 结果 |
|---|---|
| 今日无课 | 应到/已点名/未点名均为 0，空态出现「去排课」「查看本周课表」 |
| 待收款逾期 | 李小红订单显示「逾期 5 天」，点「收款」打开收款弹窗，金额 3600 |
| 退费逾期 | 王小刚退费单显示「逾期 5 天」，点「审批」打开审批弹窗 |
| 工作台内联处理 | 点待收款「收款」、退费「审批」均停留在 `/workbench` 弹窗处理，取消/关闭后无跳转 |
| 线索逾期 | 赵小天「逾期 7 天」、孙小美「逾期 2 天」，点「跟进」打开对应跟进弹窗 |
| 今日收款口径 | 当天 ¥3,600，本月 ¥64,800 |

## 七、边界

- 逾期只做展示，不发短信/站内信；收款和退费审批已在工作台内完成，线索跟进仍需跳转。
- 今日课节依赖课表周接口，取消的课节不计入。
- 线索跟进弹窗一次加载最近 50 条历史，后续可加分页。
