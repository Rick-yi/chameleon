# 07 · 报表与看板规划

> 目标：把现有业务数据变成校长、教务、财务和平台运营能直接使用的经营视图。
> 本文只做规划，不包含实现；指标口径、页面、接口、数据缺口和里程碑都在这里定下来。

---

## 一、使用角色与看板划分

| 看板/报表 | 使用者 | 核心问题 |
|---|---|---|
| 机构经营看板 | 校长/机构管理员 | 本月收了多少钱、退了多少、课消多少、还有多少续费要跟进 |
| 财务报表 | 校长/财务 | 收款、退费、净营收、渠道、课程/校区排行、明细导出 |
| 教务报表 | 教务/教学主管 | 出勤率、满班率、教师课时、课消进度、异常学员 |
| 招生报表 | 招生/校长 | 线索来源、跟进漏斗、试听转化、报名转化 |
| 平台经营看板 | 平台运营 | 租户增长、活跃、套餐分布、即将到期、机构规模 |

建议菜单结构：新增「报表中心」模块，下挂「经营看板」「财务报表」「教务报表」「招生报表」；平台端新增「平台看板」。

## 二、指标口径

> 金额统一 `BigDecimal`，保留 2 位；课时保留 2 位；时间统一 `Asia/Shanghai`，区间采用左闭右开 `[start, end)`。

### 2.1 财务指标

| 指标 | 口径 |
|---|---|
| 收款金额 | `SUM(STUDENT_ORDER.PAID_AMOUNT)`，订单状态 `PAID/REFUNDED`，按 `PAY_TIME` 统计 |
| 退费金额 | `SUM(STUDENT_REFUND.REFUND_AMOUNT)`，状态 `REFUNDED`，按退款完成时间统计（当前缺 `REFUND_TIME`，见数据缺口） |
| 净营收 | 收款金额 − 退费金额 |
| 应收金额 | `SUM(STUDENT_ORDER.AMOUNT)`，状态 `UNPAID`，按创建时间统计 |
| 实收率 | 收款金额 ÷ 应收金额（含历史应收时需限定订单范围） |
| 客单价 | 收款金额 ÷ 已支付订单数 |
| 生均收入 | 收款金额 ÷ 去重付费学员数 |
| 退费率 | 退费金额 ÷ 收款金额 |
| 课消金额（权责口径） | `Σ(消课课时 × 订单单价)`；订单单价 = 订单实付 ÷ 订单购买课时。当前流水未记录订单 id，需补 `ORDER_ID` 或按订单消耗分摊计算 |
| 课消课时 | `SUM(ABS(ATTEND 流水课时)) − SUM(ABS(RESTORE 流水课时))`，按流水创建时间统计 |

**建议同时展示两套口径：**
- 现金流口径：收款 − 退费（老板最关心）；
- 权责口径：课消金额（反映实际交付，避免预收款虚高）。

### 2.2 教务指标

| 指标 | 口径 |
|---|---|
| 到课率 | 到课记录数 ÷（到课 + 缺勤 + 请假）记录数 |
| 出勤率 | 到课记录数 ÷ 应到人数；应到 = 班级在学学员数 × 已发生排课次数 |
| 满班率 | 班级在学学员数 ÷ 班级容量，按班级/课程/校区汇总 |
| 教师课时 | 按 `COURSE_SCHEDULE.TEACHER_ID` 汇总已上课时长，或按点名扣课时汇总 |
| 课消进度 | 已消课时 ÷ 总课时，按学员/课程/班级 |
| 剩余课时预警 | 账户剩余 ≤ 阈值，或有效期 ≤ 7 天 |
| 停课/流失预警 | 连续 N 天无出勤，或剩余课时为 0 且无续费 |

### 2.3 招生指标

| 指标 | 口径 |
|---|---|
| 线索量 | 按 `CRM_LEAD.CREATE_TIME` 统计 |
| 线索来源占比 | 按来源渠道分组 |
| 跟进率 | 有跟进记录的线索数 ÷ 线索总数 |
| 试听量/试听转化率 | 试听预约数；转化 = 试听后报名数 ÷ 试听数（当前试听缺结果字段） |
| 报名转化率 | 状态为 `ENROLLED` 的线索数 ÷ 线索总数 |
| 招生成本（后续） | 市场费用 ÷ 报名人数，需要新增费用表 |

### 2.4 平台指标

| 指标 | 口径 |
|---|---|
| 租户总数 | `T_TENANT` 排除平台租户 `0` |
| 新增租户 | 按 `CREATE_TIME` 统计 |
| 活跃租户 | 近 30 天有登录或有已支付订单的租户；首版可先用“近 30 天有已支付订单” |
| 到期租户 | `EXPIRE_TIME` 在未来 30 天内或已过期 |
| 套餐分布 | 按 `PACKAGE_ID` 分组 |
| 机构规模分布 | 按租户学员数、校区数分档 |
| 预估 ARR | 套餐价格 × 租户数，仅作估算；v1 未接订阅计费，不应当作实际收入 |

## 三、页面规划

### 3.1 机构经营看板（首页）

**顶部 KPI 卡片（本月）：**
- 收款金额、退费金额、净营收；
- 课消课时、课消金额；
- 在读学员数、本月新增学员；
- 待跟进续费预警数。

**图表区：**
- 近 6 个月收款/退费/净营收趋势（柱线组合）；
- 近 30 天课消趋势（折线）；
- 收款渠道占比（饼图）；
- 课程收款排行（横向柱状图）；
- 校区经营对比（柱状图，多校区时展示）。

**待办区：**
- 待处理续费预警（Top 10）；
- 待收款订单；
- 今日/本周排课与点名完成情况。

### 3.2 财务报表

**筛选条件：** 时间范围（今日/本周/本月/上月/本年/自定义）、校区、课程、收款渠道。

**Tab/区块：**
1. **财务汇总**：收款、退费、净营收、订单数、客单价、退费率；
2. **收款趋势**：按日/月切换；
3. **渠道分析**：微信/支付宝/线下转账/现金（当前 v1 只有线下/现金）；
4. **课程收款排行**：按课程、课包；
5. **收款明细**：分页列表，支持导出；
6. **退费明细**：分页列表，支持导出；
7. **课消与收入确认**：按课程/班级/教师汇总课消课时与课消金额。

**导出：** 收款明细、退费明细、课程汇总，EasyExcel 导出；超过 5 万行建议异步导出。

### 3.3 教务报表

**筛选条件：** 时间范围、校区、课程、班级、教师。

**区块：**
1. 出勤汇总：到课/请假/缺勤人次，到课率；
2. 班级满班率：班级、课程、教师、容量、在学人数、满班率；
3. 教师课时：教师、排课次数、计划课时、实际到课课时；
4. 学员课消进度：学员、课程、总课时、已消、剩余、课消进度；
5. 异常学员：低剩余课时、长期未出勤、停课。

**下钻：** 点击班级进入班级课表/点名记录；点击学员进入学员详情。

### 3.4 招生报表

**区块：**
1. 线索漏斗：新线索 → 已跟进 → 已试听 → 已报名，显示各阶段数量与转化率；
2. 来源渠道：渠道、线索数、报名数、转化率；
3. 跟进排行：跟进人、跟进次数、报名数；
4. 试听转化：试听数、到访数、报名数、转化率；
5. 趋势：按日/月线索量与报名量。

### 3.5 平台经营看板

**KPI：**
- 租户总数、本月新增、活跃租户、30 天内到期；
- 套餐分布、机构学员规模分布；
- 预估 ARR（明确标注“估算”）。

**图表：**
- 租户增长趋势（近 12 个月）；
- 套餐占比（饼图）；
- 到期租户列表（可跳转续费/停用）；
- 租户活跃度排行（按订单数/学员数）。

> 平台看板需要跨租户聚合，必须使用平台角色鉴权，并在专用 Mapper 上显式关闭租户拦截器后手工加租户条件，不能复用业务租户查询。

## 四、数据来源与缺口

### 4.1 现有可用数据

| 数据 | 表 |
|---|---|
| 订单/收款 | `STUDENT_ORDER`（金额、实收、渠道、支付时间、课程、消耗、退课时） |
| 退费 | `STUDENT_REFUND`（金额、课时、赠课、状态、审批时间） |
| 课时流水 | `STUDENT_LESSON_FLOW`（类型、课时、排课、时间） |
| 课时账户 | `STUDENT_LESSON_ACCOUNT`（总/赠/已用/剩余/到期） |
| 学员 | `STUDENT`（校区、状态、创建时间） |
| 课程/课包 | `COURSE`、`COURSE_PACKAGE` |
| 班级/排课/点名 | `COURSE_CLASS`、`COURSE_SCHEDULE`、`COURSE_CLASS_ATTEND` |
| 线索/跟进/试听 | `CRM_LEAD`、`CRM_LEAD_FOLLOW`、`CRM_TRIAL_APPOINTMENT` |
| 租户/套餐 | `T_TENANT`、`T_TENANT_PACKAGE` |
| 机构/员工 | `SYS_ORG`、`SYS_USER` |

### 4.2 需要补的字段/表（建议 R1 一起做）

| 缺口 | 建议 |
|---|---|
| 退费完成时间 | `STUDENT_REFUND.REFUND_TIME`，确认退款时写入；报表按此时间统计 |
| 流水关联订单 | `STUDENT_LESSON_FLOW.ORDER_ID`，扣课时由分摊服务写入；用于按订单/课包确认收入 |
| 订单校区快照 | `STUDENT_ORDER.CAMPUS_ID`，下单时从学员校区快照；避免学员转校区后历史归属变化 |
| 试听结果 | `CRM_TRIAL_APPOINTMENT.RESULT`（到访/未到访/已报名/未报名） |
| 续费归因 | `STUDENT_RENEW_WARN` 已续费状态可用；如需精确续费率，增加续费订单关联 |
| 平台活跃度 | 首版用订单活跃；后续可增加租户登录日志汇总 |

### 4.3 索引建议

- `STUDENT_ORDER (TENANT_ID, PAY_TIME, STATUS)`
- `STUDENT_ORDER (TENANT_ID, COURSE_ID, PAY_TIME)`
- `STUDENT_ORDER (TENANT_ID, STUDENT_ID, STATUS)`
- `STUDENT_REFUND (TENANT_ID, STATUS, REFUND_TIME)`
- `STUDENT_LESSON_FLOW (TENANT_ID, FLOW_TYPE, CREATE_TIME)`
- `STUDENT_LESSON_FLOW (TENANT_ID, COURSE_ID, CREATE_TIME)`
- `COURSE_CLASS_ATTEND (TENANT_ID, SCHEDULE_ID, ATTEND_STATUS)`
- `COURSE_SCHEDULE (TENANT_ID, SCHEDULE_DATE, TEACHER_ID)`
- `STUDENT (TENANT_ID, CAMPUS_ID, STATUS, CREATE_TIME)`

## 五、技术方案

### 5.1 第一阶段：实时聚合（MVP）

- 新增 `snowy-plugin-report`（+`-api`），或先在 finance/student 插件内加 `report` 模块；
- 使用 MyBatis-Plus 自定义 Mapper（XML 或 `@Select`）做聚合查询；
- 所有业务租户报表 SQL 必须带 `TENANT_ID`；租户拦截器只对登记表生效，聚合 SQL 仍要显式核对；
- 平台报表使用独立 Mapper，`@InterceptorIgnore(tenantLine = "true")` + 平台角色校验 + 显式租户过滤；
- 图表接口一次返回聚合结果，明细接口分页；
- 报表数字必须能与流水/订单明细对账，建议每张报表提供“查看明细”。

### 5.2 第二阶段：日汇总表（数据量上来后）

建议表 `FIN_DAILY_STAT`：

| 字段 | 说明 |
|---|---|
| TENANT_ID / STAT_DATE / CAMPUS_ID / COURSE_ID | 维度 |
| PAID_AMOUNT / REFUND_AMOUNT / NET_AMOUNT | 金额 |
| ORDER_COUNT / PAYING_STUDENT_COUNT | 订单/付费学员 |
| ATTEND_LESSONS / RESTORE_LESSONS / NET_LESSONS | 课消 |
| NEW_STUDENT_COUNT / RENEW_STUDENT_COUNT | 新增/续费 |
| CREATE_TIME / UPDATE_TIME | 审计 |

- 每日 00:30 由定时任务汇总前一天数据；
- 支持按日/月/校区/课程上卷；
- 提供“重算某日”按钮，便于数据修正后回补；
- 首版可先实时查询，等数据量或性能有压力再上汇总表。

### 5.3 缓存与性能

- 看板 KPI/趋势接口可加 Redis 缓存 5 分钟，key 含租户、日期范围、校区、课程；
- 明细查询必须分页，单页最大 100；
- 时间范围默认本月，最大查询 1 年；导出超过 5 万行走异步任务；
- 图表查询避免 `SELECT *` 和大表全量加载。

### 5.4 权限与数据范围

- 报表菜单/按钮走 Snowy 角色授权；
- 平台看板仅 `platformAdmin`；
- 机构报表按校区/教师数据范围过滤（当前业务模块尚未接 Snowy 数据范围，报表阶段建议一并补上）；
- 财务明细/导出建议仅校长、财务角色可见。

## 六、接口草案

统一前缀 `/report`，返回 `CommonResult`，时间参数 `startDate/endDate`（`yyyy-MM-dd`）。

### 6.1 经营看板

## 九、待确认决策

1. **收入确认口径**：只做现金流（收款−退费），还是同时做权责口径（课消金额）？建议两者都做，默认展示现金流。
2. **退费统计时间**：按退款完成时间，还是按申请/审批时间？建议完成时间，已补 `REFUND_TIME`。
3. **活跃租户定义**：近 30 天登录，还是近 30 天有已支付订单？建议先用后者，数据现成。
4. **续费率定义**：按预警转已续费，还是按“到期账户在 30 天内产生新订单”？建议后者更贴近经营。
5. **平台收入展示**：v1 未接订阅计费，是否展示“预估 ARR”？建议展示但明确标注估算。
6. **报表权限**：财务明细/导出是否只给校长和财务？教师是否只能看自己的课时？
7. **导出口径**：是否需要税务/发票字段？当前表没有，首版不做。
