# 自动化可靠性升级

## 一、这次解决什么

自动化中心原来能跑通 5 条规则，但缺少生产级的“刹车、证据和归因”：

- 自动结算对单节课异常只打日志，整轮仍可能显示成功；
- 提醒先发消息再逐条写 `lastNotifyTime`，部分失败会重复或丢失；
- 手动“立即执行”直接改数据，没有影响面预览；
- 线索会按负载分给任意启用用户，没有角色过滤；
- 执行记录只有结果和条数，无法回答“处理了谁、为什么失败、有没有送达”。

本次不新增规则类型，只在现有 5 条规则上补齐正确性、护栏、触达回执和实验归因。

## 二、引擎层能力

### 1. 预览与参数护栏

- 自动化中心新增「预览」：只计算影响面，不产生副作用；「立即执行」先预览，再弹确认。
- 参数定义增加 `min/max`，后端在保存和执行前都校验。负数、超大值、非法开关值会被拒绝。
- 定时任务执行前再次取参数校验，避免历史脏参数直接生效。

### 2. 总开关、静默时段、每日上限

- `BIZ_AUTOMATION_SETTING` 新增租户级设置：
  - `PAUSED`：一键暂停全部自动化；
  - `QUIET_START/QUIET_END`：提醒类规则的静默时段，支持跨午夜；
  - `TIMEZONE`：默认 `Asia/Shanghai`。
- 静默时段只跳过提醒类规则，自动结算/线索分配不受影响；手动执行可越过静默，便于人工兜底。
- `BIZ_AUTOMATION_CONFIG` 新增：
  - `DAILY_CAP`：每规则每日成功动作上限，0 表示不限；
  - `HOLDOUT_PERCENT`：提醒类规则的对照组比例；
  - `VERSION`：配置版本。

### 3. 租约锁

- 每次执行按 `tenantId + ruleCode` 获取 Redis 租约锁，锁 10 分钟。
- 多实例、定时与手动同时触发时，后到的一轮直接跳过，不会重复点名或重复群发。

### 4. 目标级幂等与结果

新增 `BIZ_AUTOMATION_TARGET`：

- 每个目标、动作、窗口生成唯一幂等键；
- `CLAIMED → SUCCESS/FAILED/SKIPPED` 状态流转；
- 失败记录保留重试次数，最多重试 3 次；
- 每个目标记录 `LOG_ID / TARGET_TYPE / TARGET_ID / ACTION / MESSAGE_ID / EXPERIMENT_GROUP / OUTCOME_*`。

提醒规则的去重窗口由 `repeatHours` 决定；自动结算/分配/试听推进是一次性幂等键。

### 5. 触达回执

- `DevMessageApi` 新增 `sendMessageWithContentReceipt`，返回站内信 ID。
- 提醒规则逐目标记录同一个消息 ID 和触达条数；日志展示 `CREATED / FAILED / NONE`。
- 站内信已创建、接收关系已写入即视为“已创建回执”；外部短信/微信回执仍取决于后续渠道接入。

### 6. 配置审计

新增 `BIZ_AUTOMATION_CONFIG_HISTORY`：

- 记录每次开关/参数变更前后的值、版本、操作人、时间；
- 规则卡片展示当前版本与最近变更时间。

### 7. 实验与归因

- 提醒类规则支持 holdout：按 `tenant+rule+target` 的稳定哈希分组，同一目标始终在同一组。
- 对照组只记录 `SKIPPED/HOLDOUT`，不发送消息；处理组正常发送。
- `BIZ_AUTOMATION_TARGET` 保存 48 小时后的业务结果：
  - 未支付订单：是否在触达后付款，归因金额取实收；
  - 续费预警：该学员在触达后是否有新的已付款订单。
- 自动化中心「效果」弹窗展示处理组/对照组的数量、成功数、转化率和归因金额。
- 这是观察性归因，不是严格因果证明；样本量足够时再考虑更严格的实验设计。

## 三、5 条规则的变化

| 规则 | 变化 |
|---|---|
| 课节自动结算 | 只扫最近 `lookbackDays`（默认 7 天）；批量查已有点名；逐课节记录成功/失败；通知失败单独记失败，不再吞异常；结算与通知分别记账 |
| 线索自动分配 | 候选用户按角色码过滤（默认 `sales`）；角色查询只做一次；条件更新防止并发重复认领；支持预览 |
| 试听结束自动推进 | 条件更新只推进仍为「待试听」的预约；逐预约记录结果；通知回执落库 |
| 续费预警提醒 | 逐目标幂等占位；holdout 对照组；发送成功才回写提醒时间；发送失败记录失败并允许下一轮重试 |
| 未支付订单提醒 | 同上；重复窗口按 `repeatHours` 分桶；逐目标消息回执；预览显示真实影响条数 |

## 四、接口

复用原有权限，不新增权限码：

| 接口 | 说明 |
|---|---|
| `POST /biz/automation/run` | `preview=true` 只预览；否则执行 |
| `GET /biz/automation/setting` | 租户级设置 |
| `POST /biz/automation/setting` | 保存总开关/静默时段/时区 |
| `GET /biz/automation/experiment` | 规则实验/归因统计 |

首次升级会由 `P0SchemaMigration` 自动补充 `/biz/automation/setting`、`/biz/automation/experiment` 的接口权限。

## 五、验证

### 本地接口

- 非法参数 `graceMinutes=-5` 返回“参数【宽限时间（分钟）】不能小于 1”。
- 关闭 holdout 后预览未支付订单：`预览：将提醒 1 笔未支付订单`。
- 实际执行：`已提醒 1 笔未支付订单`，日志 `TARGET_COUNT=1 / SUCCESS_COUNT=1 / DELIVERY_STATUS=CREATED / DELIVERY_COUNT=1`。
- 立即重跑：`没有需要提醒的未支付订单`，没有重复目标。
- 目标表：`ORDER / o_ux_001 / NOTIFY / SUCCESS / TREATMENT / MESSAGE_ID 非空`。
- 实验接口返回 `TREATMENT total=1`。
- 暂停后执行返回“自动化已暂停，未执行任何动作”。
- 静默时段设置保存、清空均生效，`inQuietHours` 正确。
- 实时新增线索自动分配给 `sales01`（招生顾问），没有分给老师或前台，验证角色过滤生效。

### 自动化测试

- `AutomationSupportTest` 覆盖 holdout 稳定性、0/100 边界、跨午夜静默、幂等键、HH:mm 校验。
- 全量后端测试：32 个全部通过。
- 前端 `npm run build`：成功。

## 六、已知边界

- 归因是观察性统计，依赖 holdout 分组；样本很小或业务波动大时只能看方向，不能当作严格因果结论。
- 外部短信/微信没有接入，当前只记录站内信消息 ID 和创建回执。
- 自动结算“结算成功但通知失败”会记录失败，但下一轮不会重复通知（课节已有点名，规则会跳过）；失败在日志里可见，需要人工补发。
- 多实例部署依赖 Redis 租约锁；Redis 不可用时执行会失败，不会绕过锁继续跑。
- 自动分配只按角色、排除名单和当前在跟线索数，不含校区/专长/在线状态；这些需要业务数据支持后再加。
