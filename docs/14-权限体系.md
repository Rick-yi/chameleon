# 14 · 教培权限体系（角色 / 菜单 / 接口 / 数据范围）

> 目标：把「谁能看到什么、能做什么、能看谁的数据」四件事落到可配置、可验证的机制上，
> 而不是靠前端藏菜单。**菜单隐藏 ≠ 接口不可达**，接口必须有独立校验。

---

## 一、角色清单

机构开通时会自动创建「机构管理员」+ 四个岗位角色（角色码同时决定 App 端视角）：

| 角色码 | 名称 | 数据范围 | 可见菜单 | App 视角 |
|---|---|---|---|---|
| `superAdmin` | 机构管理员 | 全部（自动补齐全量业务权限） | 全部 | 经营总览 |
| `principal` | 校长/运营负责人 | 全部 | 教务全域 + 四个报表 | 经营总览 |
| `sales` | 招生顾问 | 本人（线索按跟进人过滤） | 工作台、招生线索、学员、收款台、招生报表 | 招生 |
| `teacher` | 授课老师 | 本校区 + 本人（课节/学员按授课教师过滤） | 工作台、我的课表、点名消课、学员名册 | 教学 |
| `cashier` | 前台/财务 | 全部 | 工作台、收款台、续费预警、财务报表 | 前台财务 |

角色定义见 `PlatformRoleTemplates`（后端常量），租户开通与「套用模板」都读它。

## 二、四层权限怎么落地

### 1. 菜单权限
`SYS_RELATION`（`SYS_ROLE_HAS_RESOURCE`）→ 角色能看到的页面。
前端登录时由 `loginMenu` 接口下发，PC 端按菜单渲染，App 端按视角裁剪底部 Tab。

### 2. 接口权限（业务接口登记为按钮资源）
业务接口原先没有登记到 `SYS_RESOURCE`，导致角色管理页看不到、也无法精确授权。
现在 112 个业务接口全部登记成所属菜单下的按钮资源（`CODE = 接口地址`）：

```sql
-- snowy-web-app/src/main/resources/_sql/chameleon_role_api_button.sql
INSERT IGNORE INTO SYS_RESOURCE (ID, PARENT_ID, TITLE, CODE, CATEGORY, ...)
VALUES ('b<hash>', 'menu_student_001', '学员分页', '/student/page', 'BUTTON', ...);
```

好处：角色管理页可以按接口勾选；角色模板可以按**接口前缀**批量授权。

### 3. 接口鉴权兜底（关键）
业务接口有 100 多个，逐个标 `@SaCheckPermission` 容易漏，漏标就等于**任何登录用户都能直接调**。
所以在全局过滤器里加了一层兜底：

```java
// GlobalConfigure：业务域接口必须在当前用户的接口权限清单内
SaRouter.match("/**")
        .notMatch(NO_LOGIN_PATH_ARR)
        .match("/student/**", "/course/**", "/crm/**", "/finance/**", "/biz/event/**", "/biz/automation/**")
        .check(r -> {
            String apiUrl = SaHolder.getRequest().getRequestPath();
            if (BIZ_AUTH_EXEMPT_PATH_ARR.contains(apiUrl)) return;   // 埋点上报等系统级写入
            List<String> permissionCodeList = StpLoginUserUtil.getLoginUser().getPermissionCodeList();
            if (ObjectUtil.isEmpty(permissionCodeList) || !permissionCodeList.contains(apiUrl)) {
                throw new NotPermissionException(apiUrl);
            }
        });
```

> 这条兜底是在压测中发现的：老师账号可以直接调 `/crm/lead/page`、`/student/order/page`（这些接口当时没标 `@SaCheckPermission`），
> 菜单藏了但接口能打。加上兜底后 62 项越权用例全部拦住。

### 4. 数据范围
Snowy 的数据范围挂在**接口权限**上（`ext_json.scopeCategory`），因此同一角色可以给不同接口配不同范围：

| scopeCategory | 含义 | 业务落点 |
|---|---|---|
| `SCOPE_ALL` | 全部数据 | 校长、前台 |
| `SCOPE_ORG` | 本校区（机构 = 校区） | 老师 |

「本人」维度（`SCOPE_SELF` 在 Snowy 里是空机构集合，业务表按校区过滤会查不到数据），
所以按岗位在**业务查询层**实现：

| 岗位 | 过滤规则 | 代码位置 |
|---|---|---|
| 授课老师 | 课表 = 课节授课人是我 或 课属于我带的班级 | `CourseScheduleServiceImpl.week` |
| 授课老师 | 班级学员 = 我带的班级 | `CourseClassStudentServiceImpl.page` |
| 授课老师 | 学员名册 = 我班里的学员 | `StudentServiceImpl.page` |
| 招生顾问 | 线索 = 跟进人是我 | `CrmLeadServiceImpl.page` |

角色判断统一走 `StpRoleUtil`（无登录态安全，定时任务里不会误判）。

## 三、按钮级权限（页面内的操作）

菜单可见 ≠ 页面内每个动作都能做。按钮级权限的粒度就是**该动作调用的接口**：

| 角色 | 能看到的按钮 | 看不到的按钮 |
|---|---|---|
| 授课老师 | 确认点名并扣课、撤销点名 | 新增学员、报名、收款、审批、新增班级… |
| 招生顾问 | 新增线索、跟进、安排试听、转学员 | 课表、点名、班级管理、收款审批… |
| 前台/财务 | 收款、取消订单、退费审批 | 新增线索、课表、班级管理… |
| 机构管理员 | 全部 | — |

实现方式沿用 Snowy 的按钮码机制：

1. **写操作接口标记为动作按钮**：按钮资源 `EXT_JSON = {"action":true}`（读接口只是页面级权限，不进按钮码）
2. **角色-菜单关系里写 `buttonInfo`**：授权时把该角色可用的动作按钮 id 写进 `ext_json.buttonInfo`
3. **前端用 `hasPerm(接口地址)` 判断**：

```vue
<a-button v-if="hasPerm('/student/order/offlinePay')" @click="onOpenPay(record)">收款</a-button>
```

> 按钮码直接用接口地址，省掉「按钮码 ↔ 接口」的二次映射：按钮码 = 这个动作会调的那个接口。
> 后端仍然独立校验接口权限，前端只是**少显示**按钮，不承担安全职责。

已接入按钮级权限的页面：学员管理、收款台、招生线索、课程/课包/班级管理、排课课表、点名消课、续费预警、自动化中心，以及移动端的收款、跟进/试听/转学员、点名提交。

## 四、怎么用

### 新开机构
`POST /platform/tenant/add` → 开通流程自动创建 5 个角色并授权（`TenantInitService.ensureTenantRoles`），
同时给机构管理员补齐全量业务菜单与接口权限。

### 存量机构补齐
```sql
-- 1) 登记业务接口（幂等）
mysql -uroot -p chameleon < _sql/chameleon_role_api_button.sql

-- 2) 为每个租户套用角色模板（幂等，POST /platform/roleTemplate/apply {"tenantId":"xxx"}）
```

### 存量机构补齐（按钮权限需要重新套一次）
```bash
node scripts/perm/role-scope-smoke.mjs demo   # 校验
# 重新套用模板（会重建角色-菜单关系，把 buttonInfo 一起写入）
POST /platform/roleTemplate/apply {"tenantId":"xxx"}
```

### 给员工分配角色
PC 端「系统管理 → 用户管理」里给用户勾选角色即可；
角色本身在「系统管理 → 角色管理」里可以继续调整菜单、接口与数据范围。

### 移动端视角
`store/app.js` 按角色码推导默认视角，并按角色收敛「切换视角」选项；
越权页面在 App 内直接回首页，不会出现满屏 403。

## 附：租户初始化按钮授权修复（2026-10-23）

新租户开通时，`TenantInitService` 会先复制菜单资源、再调用 `topUpAdminGrant` 补齐业务按钮。原实现遇到「菜单已授权」就直接跳过，导致管理员只有菜单、没有按钮级权限（前端 `hasPerm` 全部为 false，新增/报名/排课等操作按钮不显示）。

已改为：对已存在的业务菜单同步刷新 `ext_json.buttonInfo`，把该菜单下的动作按钮补齐。存量租户可通过平台接口 `POST /platform/roleTemplate/apply`（传 tenantId）重建一次授权。
