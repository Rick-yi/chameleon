# 集成测试基座

上一轮我判断「本机没有 Docker，无法做集成测试」——**这个判断是错的**。本机一直有自建 MySQL 8（`D:\data\mysql-8.0.39-winx64`，库 `chameleon`），记忆里也明确记着这套栈，我却把「需要 Docker」当成了前提。本轮纠正并补上。

## 一、独立测试库

集成测试会真的写数据，**绝不能连演示库**。新建独立库 `chameleon_it`，用仓库自带的初始化脚本建结构：

```bash
mysql -uroot -p -e "CREATE DATABASE chameleon_it DEFAULT CHARACTER SET utf8mb4"
export PATH="/d/data/mysql-8.0.39-winx64/bin:$PATH"
MYSQL_DB=chameleon_it SKIP_DEMO=1 bash scripts/db-init.sh
```

物理隔离，跑测试不会影响演示数据。

## 二、先修一个阻断性问题：auth 的 POM 是 invalid 的

配好测试后 Spring 上下文起不来，报：

```
NoClassDefFoundError: cn/dev33/satoken/filter/SaServletFilter
```

排查发现 `snowy-plugin-auth` 的 POM 被 Maven 判定 invalid，**导致它的所有传递依赖（含 sa-token starter）全部失效**：

```
'dependencies.dependency.systemPath' for com.huawei.welink.sdk:welink-sdk-java:jar
must specify an absolute path but is ${pom.basedir}/src/main/resources/lib/welink-sdk-java-2.1.5.jar
```

原声明：

```xml
<dependency>
    <groupId>com.huawei.welink.sdk</groupId>
    <artifactId>welink-sdk-java</artifactId>
    <scope>system</scope>
    <systemPath>${pom.basedir}/src/main/resources/lib/welink-sdk-java-${welink-sdk.version}.jar</systemPath>
</dependency>
```

`systemPath` 用 `${pom.basedir}` 相对路径，在从本地仓库解析本模块时无法求值，整个 POM 失效。

而实际上**没有任何 Java 代码 import 华为 SDK**——WeLink 走 HTTP 直连（见 `AuthOidcWeLinkRequest`）。这个依赖完全没用，还持续破坏依赖解析。

移除后 POM 恢复正常，`sa-token-spring-boot3-starter` 能正确传递。这同时解释了前几轮遇到的「删掉 jar 重新 package 后启动报 `SaServletFilter` 缺失」——根因就在这里，不是打包顺序问题。

## 三、测试基座

`@SpringBootTest(webEnvironment = MOCK)` + `@TestPropertySource` 覆盖数据源指向 `chameleon_it`。用 MOCK 而非 NONE：`GlobalConfigure` 依赖 `ServerProperties` 等 Web 容器 bean，NONE 会缺 bean 起不来。

### 一个必须注意的点

账户表在租户白名单内，**测试里没有租户上下文时，拦截器会把条件拼成 `TENANT_ID='0'`**，表现为「数据明明插进去了却查不到」。所以：

- `@BeforeEach` 里 `TenantContext.setTenantId(...)`；
- 并发任务内要**各自设置**——ThreadLocal 不跨线程继承。

## 四、并发扣课测试（3 个）

这是纯单测给不了的证据。核心用例：

> 10 课时余额，20 个线程同时各扣 1 课时

断言：只有 10 次成功、剩余恰好 0、已用恰好 10、账务不变量成立。

**结果通过**，证明条件更新 `eq(状态).ge(剩余, 扣减量)` 在真实并发下确实防住了超扣。

另外两个用例：

- 冻结账户并发扣减全部失败，余额不变；
- 15 线程各扣 1.5 课时后，剩余不为负、已用不超总量、账务不变量成立。

## 五、退费扣减一致性测试（6 个）

验证退费确认路径的条件更新：

| 场景 | 结果 |
| --- | --- |
| 余额充足扣减 | 成功，总量/剩余/赠课均正确，不变量成立 |
| 剩余不足（扣 100 / 剩 15） | 拒绝，账户不变 |
| 赠课不足（扣 100 / 赠课 24） | 拒绝，赠课不变 |
| 账户未冻结 | 拒绝，防止绕过审批直接扣课 |
| 连续扣两次 | 两次都生效但余额正确递减，仍自洽 |
| 扣到 0 后再扣 | 拒绝，剩余不为负 |

## 六、怎么跑

新增 `scripts/it.sh`，一键完成：检查 MySQL 可达 → 检查测试库存在（防止误连演示库）→ 全量 install（规避本仓库「单独构建用旧 jar」的坑）→ 运行 `*IT`。

```bash
export PATH="/d/data/mysql-8.0.39-winx64/bin:$PATH"
bash scripts/it.sh
```

### 为什么不进默认构建

`*IT` 不在 surefire 默认包含范围内，`mvn test` 不会执行它们。这是刻意的：CI 环境没有 MySQL，把需要数据库的测试塞进默认流程会让流水线长期变红。

已确认：`mvn test` 仍是 119 个单测，IT 独立运行 9 个。
