# 37 · 租户边界与敏感日志加固

> 对应“必须做”清单：权限审计接口越权、报表导出任务越权、历史日志明文密码。
> 本轮只做代码与本地验证，生产尚未发布；发布后还需要轮换被泄露的管理员密码。

---

## 一、修复内容

### 1. 权限变更审计

- `SYS_AUTH_AUDIT` 纳入租户行级隔离白名单，租户只能看到本机构记录；
- 接口增加角色校验：仅 `superAdmin`（机构管理员）或 `platformAdmin`（平台运营）可访问；
- 之前用租户 token 请求 `/sys/authAudit/page` 返回 200 且无租户过滤，属于真实越权入口。

### 2. 报表异步导出任务

- `FIN_EXPORT_TASK` 纳入租户白名单；
- 任务状态查询、文件下载按当前租户过滤，租户 B 拿到租户 A 的任务 ID 也只会得到“任务不存在”；
- 异步执行线程仍按任务所属租户恢复上下文，不影响导出本身。

### 3. 课节学员表

- `COURSE_SCHEDULE_STUDENT` 纳入租户白名单，作为防御性加固；
- 该表没有公开控制器，之前主要靠 scheduleId 间接隔离。

### 4. 历史日志脱敏

- 脱敏工具支持“JSON 字符串里再包一层 JSON”的参数结构（如 `{"tenantAddParam":"{\"adminPassword\":\"...\"}"}`）；
- 新增启动清理器：扫描包含 `password` 的历史 `DEV_LOG`，把密码值替换为 `******`；
- 脱敏后在 `EXE_MESSAGE` 追加「历史敏感字段已脱敏」标记，并重算日志签名；
- `DevLog` 增加 `@ToString(exclude = "signData")`，使签名真正基于日志内容，而不是对象地址。

## 二、本地验证

| 场景 | 结果 |
|---|---|
| 单元测试：顶层/嵌套/JSON 字符串内密码 | 3 个用例通过 |
| 后端全量单测 | 27 个通过，0 失败 |
| 启动清理器首次运行 | 处理 73 条历史日志 |
| 启动清理器再次运行 | 不重复处理（幂等） |
| 人工插入的嵌套密码日志 | `adminPassword` 变为 `******`，`EXE_MESSAGE` 有脱敏标记，`SIGN_DATA` 已重算 |
| 租户 demo 查询权限审计 | 只返回 demo 记录，看不到 scale01 记录 |
| 租户 demo 查询 scale01 导出任务 | 返回「导出任务不存在」 |

## 三、生产发布后必须做的事

代码发布不会自动轮换密码，**旧密码仍然有效**。发布后需要：

1. 用平台运营账号进入「租户管理」；
2. 对 `aiglobe` 执行「重置管理员密码」；
3. 把一次性密码交给机构管理员，并确认旧密码登录失败；
4. 确认启动日志出现历史日志脱敏记录；
5. 抽查 `DEV_LOG` 中不再有密码明文。

## 四、边界

- 机构管理员角色编码目前是 `superAdmin`；如果未来支持自定义管理员角色，需要同步调整权限审计的角色校验。
- 平台运营当前没有权限审计菜单；如果平台需要跨租户查看，应单独提供平台专用接口，而不是放开租户过滤。
- 历史日志脱敏会改变原签名，已通过标记和重算签名保持可追溯；旧签名本身原本未参与校验。
- 本地验证是单机双租户数据，生产发布后仍需用真实租户做一次越权回归。
