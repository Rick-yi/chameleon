# 课包赠送时长与正课 60 课时合规

## 一、需求

- 课包需要有「赠送时长」；
- 为应付检查，课包正课课时不能超过 60 课时；赠课不设上限，例如正课 60 + 赠送 100 允许。

## 二、字段与口径

`COURSE_PACKAGE` 新增：

| 字段 | 说明 |
|---|---|
| `GIFT_VALIDITY_DAYS` | 赠送时长（天），默认 0，可与 `VALIDITY_DAYS` 叠加 |

课时口径：

- `LESSONS` 为收费课时；
- `GIFT_LESSONS` 为赠课课时；
- 正课上限：`LESSONS <= 60`；`GIFT_LESSONS` 不设上限。

有效期口径：

- 课包总有效期 = `VALIDITY_DAYS + GIFT_VALIDITY_DAYS`；
- 下单时把总有效期快照到 `STUDENT_ORDER.PACKAGE_VALIDITY_DAYS`；
- 课时账户入账/续费时按该快照顺延到期时间，不改变已购课包。

## 三、后端校验

`CoursePackageServiceImpl` 在新增和编辑时校验：

- 课时数必须大于 0；
- 赠课课时不能为负；
- 正课课时不能超过 60；赠课不限；
- 有效期、赠送时长不能为负。

存量课包正课超过 60 的不自动修改；启动时只记录告警数量，编辑该课包时会被要求先整改。

## 四、前端

- 课包表单新增「赠送时长(天)」；
- 赠课课时下方提示「赠课不限；正课课时不能超过60」；
- 列表新增「赠送时长(天)」列；
- 提交前再次校验正课课时，后端仍是最终防线。

## 五、验证

- 新增课包 `lessons=61, gift=0` 被拒绝：`正课课时不能超过60课时`。
- 新增课包 `lessons=60, gift=100` 允许。
- 课包 `validityDays=365, giftValidityDays=30` 下单后订单快照有效期为 395 天，课时账户按 395 天计算到期。
- 存量生产课包正课均不超过 60，符合检查要求。
- 后端编译通过，前端构建通过。

## 六、发布

- 启动迁移新增 `COURSE_PACKAGE.GIFT_VALIDITY_DAYS`；
- 不影响已售订单和已生成课时账户；
- 发布前备份数据库、旧 jar 和旧 dist。
