# 29 · 学员关键数据可见

> 对应问题清单 docs/26 的 P1-20 / P1-21：学员列表只有姓名、性别、家长、状态，详情顶部也看不到剩余课时、到期和待收款。
> 这一轮把校长/教务每天最常问的四件事放到了一屏：还剩多少课、什么时候到期、在哪个班、还欠多少钱。

---

## 一、学员列表

新增四列（位于家长姓名之后）：

| 列 | 说明 | 颜色规则 |
|---|---|---|
| 剩余课时 | 该学员所有课时账户的剩余合计（含赠课、已扣减已用） | 0 红色；1～2 橙色；未报名灰色“未报名” |
| 课包到期 | 仍有余额的账户中最早到期日 | 已过期红色 |
| 所在班级 | 在读班级名称，多个用顿号连接 | 无班级显示 `-` |
| 待收款 | 该学员待支付订单的应收减实收合计 | 大于 0 橙色 |

“未报名”与“课时用完”明确区分：没有课时账户显示“未报名”，有账户但余额为 0 才显示红色 0。

## 二、学员详情摘要

详情顶部新增 5 个指标 + 风险标签：

- **剩余课时**：同上，未报名显示“未报名”；
- **课包到期**：最早到期日，过期标红；
- **待收款**：待支付订单合计；
- **所在班级**：在读班级；
- **最近到课**：最近一条出勤记录的日期；
- **风险标签**：未报名 / 无剩余课时 / 课时不足 3 / 课包已到期 / 待收款金额 / 久未到课（超过 30 天）。

摘要数据来自 `studentDetail` 接口，支付、退费、点名后重新加载详情会同步刷新。

## 三、后端实现

- `Student` 增加 5 个 `@TableField(exist=false)` 展示字段：`remainLessons / accountExpireTime / classNames / unpaidAmount / hasLessonAccount`。
- `StudentServiceImpl.page` 与 `detail` 统一调用 `fillBusinessSummary`：
  - 课时账户：按当前页学员 id 批量查询，汇总剩余、取最早到期；
  - 待收款：批量查询 `UNPAID` 订单，按 `应收 - 实收` 汇总；
  - 班级：调用 `CourseApi.listStudentClassNameMap`，只统计 `STUDYING` 的班级关系。
- 三次批量查询覆盖整页，避免逐条 N+1；所有查询走 MyBatis-Plus 租户拦截器，不会跨机构取数。

## 四、验证

| 场景 | 结果 |
|---|---|
| 测试报名（22 课时、已分班） | 列表显示 22、到期日、素描基础 A1 |
| 李小红（0 课时、待收款 3600） | 列表 0 红色、待收款 ¥3600；详情标签“无剩余课时”“待收款 ¥3600.00” |
| 只建档未报名学员 | 列表显示灰色“未报名”，详情标签“未报名” |
| 张小明（大额剩余） | 列表 262 课时、到期 2044-08-12 |
| 详情最近到课 | 显示 2026-10-20 |

## 五、边界

- “下次上课”暂未展示：详情接口没有加载未来排课，避免显示错误时间；后续可接课表接口补充。
- 列表暂不支持列配置/隐藏；移动端仍以横向滚动查看新增列，后续做移动端卡片时再收敛。
- 课包到期取“仍有余额账户的最早到期日”，已用完账户的到期日不参与展示。
