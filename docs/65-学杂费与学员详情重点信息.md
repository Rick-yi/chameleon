# 学杂费与学员详情重点信息

## 一、学杂费独立成表

### 为什么分账

课包订单（`STUDENT_ORDER`）深度绑定课时：`PACKAGE_LESSONS`、`CONSUMED_LESSONS`、`REFUNDED_LESSONS`、`PACKAGE_VALIDITY_DAYS`。财务汇总直接对它求和算出「收款额、净营收、客单价、续费率」，共 8 处查询。

学杂费（校服、教材、活动费）是一次性收入，没有课时、没有消课。若混进同一张表，只有两个出路：

- 每处查询都加类型过滤 —— 漏掉任何一处，历史报表口径会被静默污染，不会报错；
- 或者改口径接受污染 —— 客单价被校服拉高、续费率分母含非课包订单。

独立成表选用第三种：**结构上不可能污染**。课包侧所有逻辑（退费、课消、续费预警）一行未改。

### 表结构

`STUDENT_SUNDRY_ORDER`：

| 字段 | 说明 |
| --- | --- |
| `FEE_TYPE` | UNIFORM 校服 / BOOK 教材 / ACTIVITY 活动费 / MEAL 餐费 / OTHER |
| `ITEM_NAME` | 物品名称（如「夏季校服 M 码」） |
| `QUANTITY` / `UNIT_PRICE` | 数量与单价 |
| `AMOUNT` | 应收（可手工覆盖，支持打包价） |
| `PAID_AMOUNT` / `REFUNDED_AMOUNT` | 实收与已退 |
| `STATUS` | UNPAID / PENDING / PAID / REFUNDING / REFUNDED / CANCELED |

索引按 `(TENANT_ID, STUDENT_ID)`、`(TENANT_ID, CREATE_TIME)`、`(TENANT_ID, STATUS)` 建立。

### 状态与并发保护

与课包订单状态刻意区分：学杂费没有「消课」，付款即收入确认；退费走独立的退款中/已退款，不复用课包的 `REFUNDED`（那里还牵着课时回补）。

三处条件更新防并发：

- **收款**：`eq(id).in(状态, UNPAID/PENDING)` → 改 PAID，失败抛「状态已变化」；
- **退费**：`eq(id).eq(状态, PAID).eq(已退金额, 原值)` → 防重复退；部分退保持 PAID（可再退），全额退置 REFUNDED；
- **取消**：仅 UNPAID/PENDING 可取消。

**已收款的单据禁止删除**，必须先退费——否则收入会凭空消失。

## 二、财务口径：独立成栏，不做合并

`FinanceSummaryDTO` 新增 5 个字段，全部是加法：

| 字段 | 含义 |
| --- | --- |
| `sundryPaidAmount` | 学杂费实收 |
| `sundryRefundAmount` | 学杂费退费 |
| `sundryNetAmount` | 学杂费净收入 |
| `sundryOrderCount` | 学杂费单数 |
| `totalNetAmount` | 总收入 = 课包净营收 + 学杂费净收入 |

**关键决策**：`netAmount` 保持课包口径不变。因为客单价、续费率都基于它计算，混入学杂费会让两个指标同时失真。总收入单独给 `totalNetAmount`。

另外做了容错：学杂费表尚未创建（旧库首次启动）时，统计跳过并只设 `totalNetAmount = netAmount`，不影响课包报表。

## 三、学员详情页重点信息

### 新增 8 项 KPI

原 5 项（剩余课时、课包到期、待收款、所在班级、最近到课）扩到 8 项，新增：

- **累计已缴**：已付订单实收 − 已完成退费金额（与财务报表净营收口径一致）
- **学杂费已收**：有欠款时下方显示「待收 xxx」
- **下次上课**：`周几 HH:mm（本周 N 节）`，无排课显示「暂无排课」

布局从固定 5 列改为 `auto-fit minmax(120px, 1fr)`，窄屏自动换行。

### 新增「学杂费」页签

学员详情内可完成全流程：新增（含立即收款开关）→ 收款 → 退费 → 删除。按钮按权限码显隐。

### 后端字段填充

- `fillBusinessSummary`（列表/详情共用）新增 `totalPaidAmount`，**一次查询聚合**，不引入 N+1；
- `fillDetailExtras`（仅详情）填学杂费与下次上课，单独抽方法避免列表页为每行查排课；
- `CourseApi.getNextSchedule` 返回 `startTime`/`className`/`weekCount`，按学员在读班级查最近课节。

两处都做了 try-catch 降级：学杂费或排课服务异常时不阻塞详情页主体。

## 四、权限与租户隔离

- 表登记进 `TENANT_TABLES`（否则跨租户可见）；
