# 15 · 数据治理与权限审计

> 两件「看不见但迟早出事」的事：埋点表无限膨胀、权限变更没有留痕。
> 本轮全部在系统内部完成，不依赖任何外部服务。

---

## 一、埋点流水归档

### 问题

`BIZ_EVENT` 按「页面访问」级别写入，单个机构一天几千到几万条：

- 10 个机构 × 800 学员的压测数据就有 **20 万条**；
- 正常运营一年约 **700 万条/机构**（按每天 2 万估算）；
- 没有清理机制，查询会越来越慢，备份体积也会失控。

### 方案

| 项 | 值 |
|---|---|
| 触发 | 每日 03:30（`DEV_JOB` → `BizEventArchiveTimerTaskRunner`） |
| 保留期 | 90 天（`BizEventArchiveTimerTaskRunner.DEFAULT_RETAIN_DAYS`） |
| 范围 | 按租户逐个执行（租户上下文隔离） |
| 方式 | 每批 5000 条、单次最多 200 批，先查主键再按主键删（逻辑删除） |

> 分批 + 主键删除是为了避免一次大事务锁表；单次上限防止某次任务跑太久影响业务。

### 验证

把任务 cron 临时改成每分钟、插 5 条 100 天前的事件，实测：

```
>>> 埋点归档完成，保留 90 天，共清理 5 条       ← 第一次
>>> 埋点归档完成，保留 90 天，共清理 0 条       ← 第二次（幂等）
old_ev_1..5 → DELETE_FLAG = DELETED
```

## 二、权限变更审计

### 问题

角色授权、接口授权、给用户分配角色，都是「点一下就生效」的高危操作。
出问题时要回答「谁在什么时候给谁开了什么权限」，原来只有登录日志，答不上来。

### 方案

新增 `SYS_AUTH_AUDIT` 表，在三个入口写审计（写失败不影响授权本身）：

| 动作 | 入口 | 记录内容 |
|---|---|---|
| `ROLE_RESOURCE` | 角色管理 → 分配菜单/按钮 | 角色名 + 授权项数 + 菜单id列表 |
| `ROLE_PERMISSION` | 角色管理 → 分配接口权限 | 角色名 + 重置/追加 + 接口列表 |
| `USER_ROLE` | 用户管理 → 分配角色 | 用户名 + 角色id列表 |

审计内容包含：租户、操作人、动作、对象（角色/用户）、摘要、明细 JSON、时间。

### 使用

PC 端「系统管理 → 权限审计」：

- 按动作、对象类型、关键词（角色/用户/操作人）筛选
- 「查看明细」抽屉展示完整的接口/菜单 id 列表（格式化 JSON）

接口：`GET /sys/authAudit/page`（`/sys/**` 仅超管可访问）。

## 三、顺带修正

1. **任务主键被截断**：`DEV_JOB.ID` 是 `varchar(20)`，`job_event_archive_001`（21 位）被静默截断，
   导致按 id 查不到任务 → 改用短 id `job_event_arch_01`。
2. **导出按钮一直不可见**：报表页的导出按钮用的是 `hasPerm('reportExport')` 这类**未注册**的按钮码；
   而我们的按钮码是接口地址。已统一改为 `hasPerm('/finance/report/export')` 等；
   同时把「导出」接口（GET 直接返回文件流）也标记为动作按钮，否则超管自己也会被藏掉。
