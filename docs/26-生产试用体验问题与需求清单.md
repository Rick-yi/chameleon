# 26 · 生产试用体验问题与需求清单

> 试用视角：机构校长 / 教务 / 前台财务 / 招生顾问 / 平台运营 / 家长
> 试用范围：登录、工作台、招生线索、学员档案、收款台、课程/课包/班级、排课课表、点名消课、续费预警、自动化中心、经营看板/财务/教务/招生报表、平台租户与套餐、移动端、家长前台
> 试用环境：生产 `https://aiglobe.xin` 登录受阻（见 P0-01），其余流程在本机同版本 + 演示数据上逐页点选完成
> 结论：**业务主流程已经能跑通**，但“每天打开先看什么、异常了怎么处理、平台怎么持续经营”这三层还没做透；当前最影响真实使用的不是功能数量，而是**关键数据的可见性**和**待办的处理闭环**。

---

## 一、优先级定义

| 级别 | 含义 | 处理建议 |
|---|---|---|
| P0 | 阻断试用或阻断营业，必须立即修 | 本周内 |
| P1 | 每天高频使用，明显影响效率或容易出错 | 1～2 个迭代 |
| P2 | 体验增强、规模化后需要 | 排入季度计划 |

## 二、P0 · 阻断性问题

### P0-01 生产环境没有可用入口，平台运营无法开通租户

**现象**

- 生产登录页用 `demo / superAdmin` 登录，提示“机构已停用或已到期，请联系平台运营”。按部署文档，演示租户在生产停用是预期行为。
- 但用 `platform / platformAdmin` 登录，**同样提示“机构已停用或已到期”**。
- 本机环境也复现：数据库 `T_TENANT` 中平台租户 `(id=0, code=platform)` 状态为 `NORMAL`、到期时间为空，`platformAdmin` 密码哈希与默认密码一致，仍登录失败。

**影响**：平台运营进不去，就无法开通、续费、停用租户，SaaS 实际上不能对外营业；同时也没有人能处理“机构已停用”的客诉。

**需求**

1. 平台租户（`tenant_id=0`）不参与到期/停用校验，或为平台运营提供独立登录入口。
2. 登录失败必须区分原因并给出可行动信息：
   - 机构编码不存在；
   - 机构已停用（显示停用时间/操作人）；
   - 机构已到期（显示到期日、续费入口/联系方式）；
   - 账号或密码错误（保留剩余尝试次数）。
3. 启动自检把“平台账号可登录”纳入健康检查，失败时告警，而不是等人工发现。
4. 平台登录失败写审计日志（账号、机构编码、失败原因、IP、时间）。

**验收**：生产用 `platformAdmin` 能进入平台看板与租户管理；停用与到期给出不同提示且带到期日。

### P0-02 前端构建缺少门禁，当前工作区编译失败

**现象**：试用过程中 Vite 报 `QuickEnrollModal.vue`（工作台快速录入学员）`Element is missing end tag`，页面被错误遮罩覆盖，无法继续操作。该文件在试用期间仍处于未提交修改状态，说明这类问题可以直接进入工作区而没有被拦住。

**影响**：只要有一个 SFC 写坏，相关页面整体不可用；如果发生在发布窗口，会直接影响线上。

**需求**

1. 提交前/CI 强制执行 `npm run build`，构建失败阻断合并与发布。
2. 生产包只允许来自“构建通过 + 打 tag”的 commit，禁止本地手工替换 dist。
3. Vite 错误遮罩仅开发环境可见；生产环境出现组件加载失败时展示可重试的错误页，而不是白屏。

**验收**：CI 中对当前 HEAD 执行前端构建；故意写坏一个标签能稳定红灯。

---

### P0-03 平台端只有“编辑/删除”，没有租户生命周期操作

**现象**：租户管理只有“编辑、删除”。客户到期要续费、欠费要停用、管理员密码忘了要重置、要看谁在什么时候登录过，平台运营都做不了。

**影响**：每接一个客户都要靠改数据库运维，无法规模化。

**需求**（租户行内操作）

1. **续费/延期**：选择套餐与时长，生成续费记录，自动更新到期时间并恢复状态。
2. **停用/启用**：二次确认 + 原因，停用后该租户全部会话失效，登录页提示原因。
3. **重置管理员密码**：重置为一次性密码，强制首登修改，并记录操作人。
4. **登录记录**：最近登录时间、IP、设备、失败次数。
5. **操作审计**：开通、续费、停用、重置密码全部留痕，可按租户查看。
6. **到期提醒**：到期前 30/7/1 天自动提醒平台运营与租户联系人。

**验收**：不连数据库即可完成“开通 → 试用 → 续费 → 停用 → 恢复”全流程。

## 三、P1 · 高频使用痛点

### 3.1 首页与导航：打开系统不知道先看哪

| 编号 | 现象/痛点 | 需求 |
|---|---|---|
| P1-01 | 登录后默认落在“系统首页”，展示用户数、组织数、职位数、角色数、访问记录——这是运维指标，不是校长每天要看的经营数据 | 机构管理员默认落到**工作台**；“系统首页”仅平台/运维角色可见 |
| P1-02 | 业务租户侧边栏仍能看到“系统运维、开发示例”等底座菜单 | 租户初始化模板只保留业务必需菜单；开发示例、代码生成、任务调度等默认不下发 |
| P1-03 | 顶部“模块”+ 左侧“菜单”两层导航，进入后左侧默认图标态，新用户找不到“学员管理” | 默认展开当前模块并高亮；记住上次访问；提供菜单搜索与面包屑 |
| P1-04 | 没有校区切换器。学员、收款、课表、工作台都不显示校区；财务却出现“未分配校区”把收入拆成两行 | 顶部提供**全局校区切换**（全部/某校区），所有业务列表与报表跟随；下单时校区必填或默认当前校区 |
| P1-05 | 顶部搜索图标只能搜菜单，搜不到学员、订单、线索 | 全局搜索：姓名/手机号/订单号/线索，回车直达详情 |
| P1-06 | 登录页保留“手机号/邮箱/动态口令”四个页签，占位符直接写着“演示机构：demo，平台运营：platform”；页脚是“业务中台基础工程，基于 Snowy 3.6.5” | 生产登录页只保留账号密码 + 手机验证码；机构编码支持预填/二维码；移除演示提示和上游技术信息，做白标 |
| P1-07 | 密码过期提示以 toast 形式反复出现，但不提供修改入口，也不强制 | 首次登录/密码过期时弹一次强制修改；之后在头像菜单提供“修改密码”与到期倒计时 |
| P1-08 | 会话失效时页面先渲染一排 0，再弹“登录已失效”，容易被当成真实经营数据 | 先校验会话再渲染，或失败态显示“数据加载失败/重新登录”，禁止用 0 兜底 |

| P1-52 | 校区经营对比出现“未分配校区”，且金额占比不小 | 见 P1-04/P1-32；报表侧标红并给补录入口 |
| P1-53 | 移动端报表只能看，不能分享/导出 | 支持生成图片/PDF 分享给合伙人或家长 |
| P1-54 | 没有教师绩效（课时、到课率、续费率、课消）报表 | 增加教师维度报表，支持按校区/月份导出 |

### 3.10 平台端：缺运营能力

| 编号 | 现象/痛点 | 需求 |
|---|---|---|
| P1-55 | 租户列表只显示联系人/电话/套餐/限额/到期/学员数/订单数/收款金额/最近登录，没有续费、停用、重置密码（见 P0-03） | 见 P0-03 |
| P1-56 | 开通租户时联系人/电话可以为空，后面没人可联系 | 开通向导必填联系人与手机号并校验；支持多个联系人 |
| P1-57 | 套餐页面描述写“套餐、限额与功能开关”，但表格没有功能开关；只有编辑/删除 | 套餐配置拆成“限额（学员/校区/账号）+ 功能开关（报表/自动化/家长端/支付）+ 上下架/复制” |

### 3.11 家长端：当前不是一个可用的家长产品

| 编号 | 现象/痛点 | 需求 |
|---|---|---|
| P1-60 | 登录页的“前台登录”进入的是 Snowy 通用 C 端（账号+密码+图形验证码），没有机构编码、没有微信登录；家长不知道账号是什么 | 手机号验证码/微信登录；按报名时登记的家长手机号自动绑定孩子；一个家长可绑多个孩子 |
| P1-61 | 家长端没有业务页面（课表、消课、请假、通知、缴费） | 首页：孩子课表、剩余课时、最近消课、待缴费用；支持请假、调课确认、课后反馈/作业 |
| P1-62 | 通知只有站内信，没有微信模板消息/短信，也没有送达状态 | 多通道通知（微信/短信/站内信）+ 送达/已读状态；重要通知可回执 |
| P1-63 | 没有在线缴费/续费 | 微信支付续费，支付后自动开单、加课时、推送收据 |

### 3.12 权限、空态与术语

| 编号 | 现象/痛点 | 需求 |
|---|---|---|
| P1-64 | 业务角色仍能看到开发/运维菜单；手机端无权限的操作会先展示再报 403 | 菜单与按钮按角色收敛；无权限入口不显示；越权给出“联系管理员开通”的明确提示 |
| P1-65 | 空态与失败态混在一起：接口失败时页面显示 0 或“暂无数据” | 空态、加载中、失败态三态区分；失败给“重试/重新登录” |

## 七、口径与数据一致性问题清单（建议单独建一张校验表）

| 指标/数据 | 观察到的现象 | 需要确认的口径 |
|---|---|---|
| 在读学员 | 工作台 5、学员管理 3 | 是否含停课/未报名/已结课 |
