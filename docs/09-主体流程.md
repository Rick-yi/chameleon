# 09 · 主体流程

> 把系统拆成 9 条主干流程，每条给出：谁在用 → 经过哪些模块/表 → 状态怎么流转 → 关键规则 → 当前实现状态。
> 规则细节见 [docs/05](05-核心业务逻辑细化.md)，报表口径见 [docs/07](07-报表与看板规划.md)。
> 状态标记：✅ 已实现并可验证 ｜ ⚠️ 部分实现（缺口已注明）｜ ⛔ 未实现。

---

## 流程零 · 工作台与待办（所有角色）

```
登录后 → 工作台（待办聚合 + 快捷入口）
        → 待收款订单 / 今日课节 / 待审批退费 / 待跟进线索 / 续费预警 / 今日收款
        → 点一下直达对应处理页（带参跳转）
```

- 工作台一次拉取 6 个板块，单板块取数失败不影响其它板块（无权限时降级为空）
- 快捷入口：报名购课 / 收款台 / 排课表 / 点名消课 / 招生线索 / 经营看板
- 「收款台」把下单、收款、取消、退费审批集中在同一页，行内操作，不必进学员详情 ✅

## 流程一 · 租户开通与平台运营（平台方）

```
平台运营 → 租户管理 → 开通租户（机构编码/套餐/到期时间）
        → 模板初始化（总部+校区 / 机构管理员 / 角色+菜单授权 / 配置+字典）
        → 租户日常使用（到期扫描 → 停用 → 续费恢复）
```

| 环节 | 实现 |
|---|---|
| 开通 | `T_TENANT` + `TenantInitService` 一次事务内建组织、管理员、角色、菜单授权、配置字典 |
| 套餐能力 | `T_TENANT_PACKAGE` 的学员数上限 / 校区数上限 / 功能开关（`funcConfig`）已生效：新增学员、超限拦截；关闭功能后对应菜单不再下发 ✅ |
| 隔离 | 业务表走 MyBatis-Plus 租户拦截器；文件按租户分桶；字典缓存切租户同步重建 ✅ |
| 到期 | 每日 01:00 扫描 → 到期租户置停用（登录即被拦）；平台看板展示到期倒计时与活跃度 ✅ |
| 缺口 | 微信支付/在线购买、自助注册开通、到期提醒推送 ⛔ |

## 流程二 · 招生获客与转化（招生老师）

```
线索录入（姓名/家长手机/意向课程/来源）
   → 跟进记录（方式/内容/下次跟进时间）
   → 试听预约（课程/时间/结果）
   → 转化：报名购课（生成订单）
```

- 表：`CRM_LEAD` / `CRM_LEAD_FOLLOW` / `CRM_TRIAL_APPOINTMENT`；转化写 `STUDENT`（带来源线索 id）
- 状态：线索 `新线索 → 已跟进 → 已试听 → 已报名 / 已流失`；试听 `待试听 → 已完成 / 已取消`，结果 `待定 / 有意向 / 无意向`
- 报表：线索漏斗、来源渠道、跟进排行、试听转化（`/crm/report/*`）✅

## 流程三 · 报名与收款（前台/财务）

```
选课包 → 订单（价格/课时/赠课/有效期/校区 快照）
      → 线下收款登记（渠道 + 实收）
      → 课时账户入账（总额 = 购买 + 赠课，有效期顺延）
      → 续费预警置为「已续费」
```

- 关键规则：订单创建时快照课包信息（改价不影响已购）；同一学员同课包只能有一张待支付订单（应用层校验 + `UK_ORDER_UNPAID` 唯一索引兜底）
- 支付回调行锁（`SELECT ... FOR UPDATE`）防重复入账 ✅
- v1 只有线下收款登记，线上支付回调接口保留待接 ✅（线上支付 ⛔）

## 流程四 · 排课与课表（教务）

```
班级（课程/教师/教室/校区 + 周课表模板）
   → 批量生成排课（按周模板展开 N 周）
   → 周课表（班级 / 教师 / 教室 视角）
   → 调课（原排课置「已调」+ 新排课 + 变更记录 + 通知落库）/ 取消排课
```

- 冲突检测：同教室 / 同教师 / 同班级在同日同时段重叠即冲突；生成时**任一冲突整体失败**，不落库
- 幂等：与已有排课（班级+日期+起止时间）完全一致的自动跳过，不会重复生成
- 课表模板未填教室/教师时，自动沿用班级的默认教室与默认教师
- 生成弹窗直接展示该班「固定课表」摘要与生成区间（周一 ~ 结束日），不用去班级页对照
- 预览：`generate` 带 `preview=true` 只返回「计划 N / 新增 M / 跳过 K / 冲突清单」，不写库
- 课表查询：`/course/schedule/week` 整段一次取回（不分页），带班级名/课程名/教师名
- 课表卡片标注点名状态（未点名/部分点名/已点名），并可一键进入点名 ✅
- 三种视角随时切换：**周视图**（时间×日期网格）、**日视图**（当天课节清单 + 教室占用统计）、**教师视图**（按教师分组、按天列出）✅
- 冲突可视化：同一日期时间重叠且教室/教师相同的课节在页面上标红「冲突」，并汇总冲突节数 ✅
- 课表导出：按当前筛选导出 Excel，含「课表清单」（一行一节课，可直接打印）与「周视图」（行=时段、列=日期）两个工作表 ✅
- 课表模板可直接在排课页编辑保存，不必回班级表单 ✅
- 班级表单的校区、教师改为下拉选择；每周固定课表用「周几 + 时段 + 教室」结构化录入，不再手填 JSON ✅
- 取消排课前必须先处理点名记录（有点名不允许直接取消）✅

## 流程五 · 点名与消课（教师）

```
按排课点名（到课 / 请假 / 缺勤）
   → 按规则计算应扣课时（课包配置 > 课程配置 > 默认：到课必扣、缺勤默认扣、请假默认不扣）
   → 课时账户扣减 + 课时流水（记录归属订单）
   → 撤销点名：按原流水逐笔回补，并回退到原订单的已消耗课时
```

- 课时挂在「课程」上而非「班级」：同一课程下多个班级共用一个课时账户，详见 [docs/05](05-核心业务逻辑细化.md) 的关系模型一节
- 点名前校验学员「在班 + 在读」，防止给他人扣课 ✅
- 课时不足 / 未购课 / 账户冻结的学员**不再拖垮整班**：本次不消课、写入未消课名单并说明原因 ✅
- 点名页显示每个学员的剩余课时（未购课标红），点名完成提示「已消课 N 人 / 未消课 M 人及原因」 ✅
- 点名页先列「当日课节」卡片（含点名状态与应到人数），点一下直接进入该节次点名；也支持从工作台/课表带参直达 ✅
- 消课流水按「先进先出」分摊到订单，跨订单时拆成多条流水，支撑按订单精确确认收入 ✅

## 流程六 · 续费预警与退费（教务/财务）

```
续费预警（每日 02:00 扫描：剩余课时 ≤ 阈值 或 课包 7 天内到期）
   → 机构待办 + 通知落库
   → 续费（一条请求完成下单 + 收款 → 入账 → 预警置「已续费」）

退费：申请 → 审批（通过则冻结账户）→ 确认退款（按订单核算可退购买课时，赠课作废）
      → 账户清零 / 撤销则解冻
```

- 退费只退「该订单已购买但未消耗」的课时，赠课随订单作废
- 同一订单只允许一张在途退费单
- 入口统一在「收款台」：订单与退费单双页签，状态卡片可点即筛，支持按学员姓名/手机搜索 ✅
- 续费在「续费预警」页一键完成：`/student/order/renew` 把下单与收款放在同一事务，课时入账后预警自动置为「已续费」 ✅

## 流程七 · 报表与经营分析（校长/财务/平台）

```
业务数据（订单/退费/流水/点名）
   → 每日 00:30 汇总日汇总表 FIN_DAILY_STAT
   → 看板 / 汇总 / 趋势 / 排行 / 课消与收入确认 / 教务报表 / 招生报表 / 平台看板
   → 对账（报表口径 vs 业务明细）
   → 导出（同步小数据量 / 异步任务大批量）
```

- 看板/汇总/趋势在「区间已闭环且无校区课程筛选」时走日汇总快路径，响应带 `dataSource` 标识
- 课消金额（权责口径）= 消课课时 × 订单购买课时单价；退费销课退回的是未消耗课时，**不再冲减**收入
- 对账：收款/退费按区间比明细直算 vs 报表口径；课消比「有流水账户」的流水净消耗 vs 账户已用；历史无流水数据单独提示 ✅

## 流程八 · 权限与数据范围（平台方配置，机构方使用）

```
角色授权（菜单 + 接口权限 + 数据范围 scopeCategory）
   → 登录后下发菜单（受租户功能开关与平台专用资源过滤）
   → 接口级 @SaCheckPermission 校验
   → 业务查询按可见机构（校区）过滤
```

- 数据范围取值：任一授权为 `SCOPE_ALL` → 不限制；否则取并集按校区过滤
- 教师维度：非管理角色在教务报表中自动收敛到本人带的班级与学员 ✅
